Compose every missing selected role

A valid Mulgae root has an accepted required role and a failed selected optional role. May compose omit the optional failure, replace the accepted role, or retry blindly after publication becomes uncertain? What changes when the retained source is missing?

No to all three shortcuts. The failed optional role still needs a committed rerun, the accepted root role remains in place, and uncertain publication requires inspection of the exact returned run. A missing required source blocks the source-validated path.

M07 · Direct source

Select an exact ordinary root

Compose requires an explicitly selected ordinary root, which may be a committed incomplete review or a verified failed-run recovery source.

The root validator checks the expected run identity, ordinary review run type, incomplete coverage, valid target digest, policy and role set, session identity, and source reference. Its error wording says “committed incomplete ordinary review”; the ADR explicitly includes a verified recovery source as another root basis. This does not imply that a failed run acquired a final review. Recovery references use a run ID and manifest hash, never a synthetic review ID. M-S06 · service.go:101–116 M-S10 · ADR:48–59

M08 · Direct source

A failed selected optional role cannot be omitted

Compose requires a committed rerun for every missing selected role, including a failed optional role regardless of its required flag.

The service constructs its missing-role set from Outcome == "failed" and HasAttempt, without checking Required in that selection. The number of admitted recoveries must match that set. This does not turn skipped or not-applicable roles into failed selected roles. M-S05 · service.go:61–71, 94–96 M-S10 · ADR:48–53

For the stated two-role root, the accepted required role needs no replacement; the failed selected optional role needs one admissible committed rerun. Older artifacts remain readable, but an old mapping that omitted a failed role is rejected under the documented new-mapping rule. M-S10 · ADR:79–81

M09 · Direct source

Preserve the accepted root role

Compose rejects a recovery that would replace an accepted root role and builds unreplaced accepted roles from the root.

admitRecovery returns CompositeRoleAlreadySatisfied when the root role is accepted. In buildResult, the default source is the root; a recovery source is selected only for a role present in the admitted recovery map. Therefore the accepted required role in the question stays rooted in its original accepted result. M-S06 · service.go:165–175 M-S07 · service.go:320–328

M10 · Direct source

A rerun label alone is insufficient

Recovery admission validates target identity, report integrity, and transitive same-role lineage before accepting the recovery mapping.

The recovery must be a one-role committed rerun with complete or degraded coverage, match the root target digest and session, and have an accepted terminal role result. “Degraded” is explicitly admitted here; it is not evidence of an unqualified clean review. M-S06 · service.go:151–175

The ADR bounds lineage to 128 links. At the root boundary, the source review identity or recovery hash must match, and the chain must end at the failed root-role attempt. The supplied code rejects missing intermediate sources. M-S10 · ADR:48–53 M-S06 · service.go:198–212, 221–224

Report validation checks attempt and provider binding, digest format, positive declared length, Markdown content type, and safe path. The shown byte-length and byte-digest checks are conditional on bytes being present; this excerpt should not be described as unconditional verification of loaded report bytes. Other validator implementations and actual stored bytes are not supplied. M-S08 · service.go:520–528

M11 · Direct source

Reconcile uncertain publication by exact run identity

After uncertain compose publication, inspect the exact returned composite run before repeating the mapping; do not blindly retry the mutation.

The README calls the same exact mapping idempotent, but explicitly requires inspection when CLI publication returns reconciliation_state: status_required. For MCP, it documents composite_publication_incomplete with deterministic non-null session_id and run_id, and retryable: false. These are documented response properties, not values observed for this explanation. Idempotence does not erase the reconciliation step. M-S09 · README.md:770–782

M12 · Qualified inference

A missing required source blocks this composition path

If the retained root or a required intermediate lineage source cannot be read, the shown compose path cannot establish an admissible composition from diagnostics alone.

A root-read failure returns CompositeValidationFailed with committed root is unavailable. An intermediate lineage read failure returns CompositeLineageMismatch with recovery lineage source is unavailable. The inference is limited to sources this mapping actually needs; it does not say every unrelated missing artifact blocks every composition. M-S05 · service.go:53–56 M-S06 · service.go:221–224

The README directs an authorized new review when a recovery source is missing. The ADR disallows promoting diagnostic logs into accepted results and treats a present invalid source as a fail-closed case. Neither substituting invented evidence nor reusing a matching-looking run ID supplies the missing proof. Any uncertain publication must still be reconciled as described in M11. M-S09 · README.md:761–762 M-S10 · ADR:74–77

func validateRoot(root Source, expected domain.RunID) error {
	if root.RunID != expected || root.RunType != domain.RunTypeReview || root.Coverage != domain.CoverageIncomplete {
		return fail(domain.CompositeValidationFailed, "root must be the exact committed incomplete ordinary review", nil)
	}
	if !validDigest(root.TargetSHA256) {
		return fail(domain.CompositeTargetDigestInvalid, "root target digest is invalid", nil)
	}
	if !root.Threshold.Valid() || len(root.Roles) == 0 || len(root.Roles) > len(domain.FixedRoleOrder()) {
		return fail(domain.CompositeValidationFailed, "root policy or role set is invalid", nil)
	}
	if _, err := domain.ParseSessionID(root.SessionID.String()); err != nil {
		return fail(domain.CompositeValidationFailed, "root session identity is invalid", err)
	}
	if _, err := sourceReference(root.RunID, root.ReviewID, root.RecoveryManifestSHA256); err != nil {
		return fail(domain.CompositeValidationFailed, "root source identity is invalid", err)
	}

M-S09 · Compose and publication reconciliation

mulgae@cef337cf927b820316f42a41f1441fbc653203f8:README.md:761–782

Accepted roles are retained. A missing recovery source requires a new review
when authorized; old diagnostic-only runs cannot be recovered retrospectively.

After every missing selected role has a committed rerun, combine the results:

```bash
mulgae compose --root-run r_... --recovery-run r_... --output json
```

The same exact mapping is idempotent. If publication returns
`reconciliation_state: status_required`, inspect the returned composite
`run_id`; do not blindly retry an uncertain mutation. Use `inspect` to obtain
composite finding IDs and availability, then `read-finding`, `read-report`, or
indexed `excerpt` for receipt-bound content. Attached MCP exposes the equivalent
inspection and resources. Newly published composites retain copied evidence;
historical composites can report it unavailable. Existing `status`, `report`,
and redacted `export` behavior remains supported.

The MCP `compose_review` equivalent reports an uncertain publication as
`composite_publication_incomplete` with deterministic non-null `session_id`
and `run_id` values and `retryable: false`; inspect that exact run before
repeating the mapping.

M-S10 · Accepted recovery ADR

mulgae@cef337cf927b820316f42a41f1441fbc653203f8:docs/architecture-decision-records/composite-review-recovery.md

Lines 48–59

`compose` requires an explicitly selected ordinary root and one committed
rerun for every missing selected role, regardless of its `required` flag.
The root may be a committed incomplete review or a verified recovery source.
Trusted code checks target identity, report integrity, and transitive same-role
lineage, bounded to 128 links, before recomputing the root policy. It preserves
accepted root roles and rejects incomplete or ambiguous mappings.

Recovery references use a run ID and manifest hash, never a synthetic review
ID. Reruns derived from recovery use v2 run/final schemas; composites rooted in
recovery use v2 composite schemas. Their deterministic identity includes the
root recovery hash. Existing v1 reads and previously valid v1 composition
identities remain unchanged.

Lines 74–81

There is no retrospective recovery of v0.1.19 diagnostic-only runs, promotion
of logs into accepted results, or recovery after forced process termination or
power loss. A missing manifest is unavailable; a present but invalid source
fails closed. Operators must reconcile exact IDs before any retry.

The selected-role rule also corrects v0.1.19 composition admission: new mappings
must recover every selected role, including optional roles. Older artifacts
remain readable, but an old mapping that omitted a failed role is rejected.
