**Baseline:** Revision 4 as amended by the owner's personal-developer and directory-result directions, D-08 and D-09 in [decisions](decisions.md). Normal JavaScript, multiple HTML pages per result directory and minimal input/output friction are required. `Must` statements are delivery requirements, not current behavior. ## Product invariants

1. The owner trusts chosen generated/imported content to execute ordinary web code. Its scripts and source text do not themselves authorize Haeryong management actions or inherit the native bridge. This is a personal tool with ordinary browser limits, not a public hostile-code hosting service.
2. Published explanations and authored provenance are immutable; display overlays, personal state and lifecycle are separate records.
3. Personal review completion through Haeryong is explicit and version-specific. AI workflow credentials cannot mark or transfer Reviewed; AI may recommend revisiting. This is an application authority rule, not a claim that Haeryong confines every program run by the same OS user.
4. Logical references never silently follow latest, restore deleted content or disclose unauthorized targets.
5. The daemon is the supported library mutation authority. Haeryong clients, managed jobs and its skill use validated service operations instead of direct SQL or arbitrary library-file writes. External tools retain the owner's normal environment; no same-user OS containment is promised.
6. A retention duration is not permission to purge; AI findings never authorize deletion or re-publication.
7. Source changes trigger assessment, not automatic proof of outdated content. Historical truth and current guidance remain distinct.
8. Subscription access is not assumed to permit arbitrary deployment. No hidden API billing fallback.
9. Remote access is first-class but opt-in/private. No public hosting, extra exposed interfaces or Tailscale enrollment is performed by this specification.
10. A failed validation gate remains failed even when a fallback UI or fixture allows other work to be demonstrated.
11. A document is a result directory, and a version is its complete immutable snapshot. A large folder, missing index.html or unsupported preview format is not invalid content. Do not silently omit hidden files, rename paths, flatten pages, rewrite originals or truncate imports/exports.
12. No fixed artifact byte, file-count or depth ceiling is a Haeryong product rule. Finite chunk sizes and worker concurrency control memory and scheduling, not total input/output. Actual device/filesystem/browser capabilities remain observable operating conditions.

## Scope exclusions

Initial scope excludes multi-user collaboration, public publishing, universal malicious-code/network containment, an independent identity/elevation platform, automatic multi-daemon replication, offline browser synchronization, native mobile apps, full IDE/code editing, autonomous source changes, broad provider support, video generation and elaborate graph visualization. General workflow orchestration remains outside Haeryong. Aquarium can invoke the Haeryong-owned skill without becoming a runtime dependency. Gul retains the operational-console role; Doksuri retains general knowledge organization. Haeryong owns source-grounded explanation versions and their evidence, references and personal review.

## Knowledge quality before contract freeze

G-VALUE in EPIC-001 evaluates explanations from two approved real projects before freezing package/API/viewer contracts. [Knowledge-quality evaluation](testing/knowledge-quality.md) separates citation resolution from semantic support, records observation/inference/illustration/trace labels, compares useful interaction with a Markdown/ADR explanation, and tests direct, indirect, irrelevant and historical source-change cases. A cheap real reader-task worksheet starts before the full spike; later reader, AI and remote milestones reuse it and record actual use. The initial 3–5 explanations and roughly 20–30 material claims are a proposed starting sample, not measured accuracy or a statistical guarantee.

The same corpus is reused for real generation/Q&A, connected remote reading, maintenance and release. User Reviewed is independent of these evaluations. Missing source and incomplete coverage remain explicit; a passed small sample does not certify global freshness or general correctness.

Portability includes a faithful directory/ZIP export of selected original files, paths, represented empty directories and preserved link metadata. Haeryong metadata and version/page-anchored personal/relationship records are separate optional exports; they do not require rewriting author files. Export is distinct from operator backup and never silently includes source bytes outside the selected artifact or retained-source scope. The contract and delivery scope are defined in [CLI](contracts/cli.md) and [package](contracts/package.md).

## Proposed quality targets

These are test targets to ratify in EPIC-001, not measured capabilities: use a 5,000-version synthetic corpus for search and list tests; exercise 10,000 canonical edges; test three simultaneous owner-client sessions plus one configured background worker. Record whether clients are real devices, browser sessions or simulations, and calibrate the baseline at TASK-001-06. This load test does not replace Stage A's real private second-device workflow. Target p95 metadata API latency below 300 ms on the recorded test host, excluding external AI and content download. Record storage size and dataset shape. Do not turn these sample loads into unsupported production limits.

The [configuration contract](contracts/configuration.md) separates owner-selected AI work budgets from artifact I/O. Large files, inventories and JSON context use streaming, chunks or stored references so a control-message or proxy request size is not a hidden document cap. Actual failures identify the affected operation and support recovery; unsupported local preview leaves the preserved file available for download. Accessibility behavior is defined in [the UI design system](ui/design-system.md), and performance/coverage methods in [test strategy](testing/test-strategy.md).
