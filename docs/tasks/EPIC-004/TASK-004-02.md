# TASK-004-02: Implement text and region search

## Outcome

Index eligible content and validate useful Korean/code retrieval without needing a graph/vector service.

## Inputs

- [data-model.md](../../data-model.md)
- [ui/screens.md](../../ui/screens.md)
- [testing/fixtures.md](../../testing/fixtures.md)

## Implementation work

1. Extract available static text and optional page/region summaries across all imported HTML pages without executing them. Stream/index incrementally with visible progress; no file count or HTML-size cutoff silently drops the rest of a directory.
2. Index document/page titles, topics and preserved paths, maintaining changes on publish/lifecycle transitions. Search results retain exact version/page_path and optional region context; attachment paths remain discoverable even when no body preview/indexer exists.
3. Add ranked scoped search, pagination and filters with explicit archive handling.
4. Reuse the initial Korean/code query worksheet, add owner-real queries and report failures against the calibrated X09 expectations without weakening denied/trash exclusion.

- SQLite FTS/search adapter.
- Library search UI.
- ranked query fixtures.

## Delivered result

Every imported HTML page is extracted statically, without executing it: text,
titles, topics, preserved paths and page-local DOM and `data-haeryong-region`
anchors. A durable `derived_index` job indexes them incrementally with visible
progress, checkpoint and restart recovery and lifecycle-aware cleanup. No
file-count or HTML-size cutoff drops content, and attachment paths stay
discoverable without previews.

Authenticated GET/HEAD search and `haeryong search` return ranked results with
exact version, page_path and optional region identity. They support project,
lifecycle, version and kind filters with explicit archive handling and
visible-state-bound cursors. Eligibility-filtered coverage and safe index
reasons report unindexed or unsupported content separately from no-match. Within
equal evidence, results alternate across pages (approved ranking amendment A1).
Library search (S03) is enabled behind `features.search` in the browser, native
and desktop clients over that one server ordering.

On the final candidate, the frozen X09 worksheet (18 rows), the adopted
calibration40 (40/40) and the agent-predeclared real-sample worksheet RC01–RC14
pass. RC03's original rank-6 miss is preserved together with its repair.
Labelled seeded scoped, denied and trash canaries show no leak through results,
counts, snippets, cursors or events. Real trash and restore transitions repeat
in TASK-005-03 and TASK-005-06. No owner-authored queries were added, so owner
use remains unmeasured. The
[search evidence record](../../testing/text-region-search.md) and the
[relevance worksheet](../../testing/search-relevance-worksheet.md) describe the
executed final-candidate checks and their limits.
