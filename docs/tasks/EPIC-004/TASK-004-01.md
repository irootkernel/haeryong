# TASK-004-01: Implement project scopes and bounded source observation

## Outcome

Provide approved source registration plus the minimal exact-revision reader and deterministic change observation needed by the connected reader, before the wider managed-AI broker.

## Inputs

- [contracts/source-access.md](../../contracts/source-access.md)
- [contracts/http-api.md](../../contracts/http-api.md)
- [ui/screens.md](../../ui/screens.md)

## Implementation work

1. Implement remembered source/project registration, provider-disclosure choices and source_mode_default (initially pinned) through the normal owner settings flow. Use GET /configuration and POST /configuration/plans with scope kind:project and project_id, then the existing plan commit route; do not add a remote filesystem browser. Apply selected project/lifecycle filters to discovery/counts/snippets without creating a separate administrator permission hierarchy.
2. Implement exact-revision lookup/read and direct-evidence comparison. Capture the selected target once and hash the actual bytes read. Existing external agents retain the owner's normal environment; managed reads record actual behavior and request confirmation only for a new source/provider scope.
3. Implement POST /versions/{id}/source-evidence/{evidence_id}/verifications and its history read using the exact-source reader. Reuse remembered source authorization; no provider call or per-read approval is needed. Preserve authored evidence and attach the separate service_verification outcome under the [source-access contract](../../contracts/source-access.md). Enable the existing Evidence action only now; import never requires this check or author-supplied quote/digest.
4. Persist source availability and change observations separately from semantic freshness. Direct relevant changes set reassessment_required for the recorded target and actual version/page/region scope. Persist captured_at when the target is selected, and record each required observed/unavailable unit so summaries can reconcile to the fixed scope; unchanged evidence leaves semantic status unassessed, and missing/denied source remains explicit. Captured reads are not provider input observations, and later cited-source checks cannot rewrite original input provenance.

## Required deliverables

- Approved source registry and read models.
- Minimal exact-revision source reader/change observer, imported-evidence verification/history, enabled Evidence action and reader status API.
- S09/source context states and direct/indirect/missing evidence fixtures.

## Observable completion and tests

- [ ] T-004-01-01: X15: direct source changes set target-scoped reassessment_required, while unrelated commits never produce an outdated verdict. Target identity and captured_at are fixed at capture, preserved across restart and unaffected by later observation/assessment completion times.
- [ ] T-004-01-02: Missing/denied source and incomplete or indirect coverage cannot appear as verified current source. Per-unit records identify inspected and unavailable page/version/optional-region scope; a required unit cannot disappear from the denominator to fabricate complete coverage.
- [ ] T-004-01-03: A cross-project link does not itself expand remembered source/provider permission; repeated reads within an approved project do not prompt again, and exact bytes remain consistent under file races. Project-scoped configuration plans preserve remembered provider/source choices and initial pinned default; a changed default cannot retarget an already captured request.

- [ ] T-004-01-04: Check imported evidence without running AI: exact source bytes yield captured when no comparison was supplied, matched or mismatch for supplied byte/quote expectations, and unavailable for an inaccessible target. Original author evidence stays unchanged, service verification/history survives restart, matching receipt replay returns the same check, and no outcome alone claims semantic support or observed generation input.
