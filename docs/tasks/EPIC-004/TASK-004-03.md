# TASK-004-03: Implement canonical pinned references

## Outcome

Store optional authored relationship metadata and resolve exact target document/version/page/region under access rules, while preserving ordinary HTML links independently.

## Inputs

- [contracts/package.md](../../contracts/package.md)
- [contracts/http-api.md](../../contracts/http-api.md)
- [data-model.md](../../data-model.md)

## Implementation work

1. Validate explicitly supplied Haeryong reference IDs and page-local DOM context consistently; a manifest or predeclared region inventory is not required to read a directory.
2. Preserve submitted exact target identities. Create validated canonical edges only for authorized exact resolution; unresolved or unavailable references remain explicit metadata and do not block directory publication or retarget to latest.
3. Differentiate authorized historical target-gone state from unknown/denied new target without disclosing hidden metadata. Ordinary relative/external hrefs work without registration as library references.

## Delivered result

Optional authored reference metadata, including `from` page/region and relation,
is additive in the embedded and machine schemas, and a plain directory without
metadata still imports. Migration 9 stores the immutable authored declarations,
their materialization state and one structural edge per resolvable exact
reference, with UUIDv5 edge identity and indexed target lookup. Publication
commits first; each version then gets a separate references `derived_index` job
that runs only after its own search extraction is terminal. That job resolves
outgoing declarations and late incoming targets in bounded, checkpointed passes
and recovers after restart. A new target version never retargets an existing
pin, and ordinary relative or external hrefs stay ordinary HTML.

Authenticated GET/HEAD `/api/v1/versions/{id}/references` and
`/references/resolve`, and `haeryong references list|resolve`, project each
declaration under current two-endpoint eligibility at read time. Hidden,
unknown, trashed and denied targets stay unavailable, without titles, bodies,
labels, edge IDs or counts. An authorized historical target with a pre-existing
structural edge returns 410 `TARGET_GONE` with only its document and version.
Reads write nothing. Source-only cursors and `references.updated` events stay
independent of hidden target outcomes. The CLI follows the shared error registry.

The shared Reader, in the browser and native clients, opens a marked reference
only when `capabilities.features.references` is true. One bound resolver call
then opens the exact pinned document, version, page and page-local region across
projects, and the host binds its region selection. Return goes to the saved
source context and position. Back/Forward and reload keep the exact once-encoded
route; with the capability absent or false, the link stays an ordinary link.

On the final candidate these passed:
- the canonical gate;
- the synthetic F03/F13 Chrome and native drivers;
- the real-sample Gaori `G12` → Mulgae `M11` case in Chrome and in the pinned
  Wails build, against a labelled synthetic successor;
- the seeded `manual_references` matrix;
- the existing Reader, evidence and search regressions.

Native initial programmatic focus is recorded as a limit; its recovery after
