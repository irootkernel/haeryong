# TASK-004-04: Implement backlinks and separate related panels

## Outcome

Expose incoming references from canonical edges and reserve a truthful UI surface for later overlays.

## Inputs

- [contracts/http-api.md](../../contracts/http-api.md)
- [ui/screens.md](../../ui/screens.md)
- [data-model.md](../../data-model.md)

## Implementation work

1. Query incoming/outgoing validated edges with exact version/page/optional region anchors and current scope/lifecycle filters. Keep optional unresolved target metadata visible only within its authorized source context, without inventing validated backlinks.
2. Show authored references, source-backed relations and later suggestions separately.
3. Add deterministic derived-index validation/rebuild operation without AI.

## Required deliverables

- backlink query/index consistency.
- Reader Links panel.
- visibility tests.

## Delivered result

Authenticated GET/HEAD `/api/v1/versions/{id}/backlinks` and `haeryong backlinks
list` return the validated canonical edges into an exact version, optionally
scoped to a page or page-local region. Rows come from the existing reverse index
in bounded raw slices, are checked against their canonical base rows, and are
admitted only when both endpoints are eligible under current scope, grants and
lifecycle. Labels, counts and cursors use admitted rows only, and unresolved
declarations never become backlinks. `edge_count` is reported separately from
`referring_document_count`. The references list adds live outgoing counts
(`edge_count`, `referenced_document_count`) that describe the same eligible state
as its rows, without changing its source-only cursors.

Owner-only GET/HEAD `/api/v1/versions/{id}/indexes/validate` and POST
`/indexes/rebuild`, with `haeryong indexes validate|rebuild`, check a version's
search index against its immutable inventory and deterministic extraction, and
its reference materialization and reverse index against the canonical edges.
Results are `consistent`, `inconsistent` or `incomplete` with safe reasons, and
every completed validation exits the CLI with 0. Rebuild re-enters the
version's terminal search and reference work at schema revision 9 without AI.
It repairs reverse-index content with `REINDEX`, keeps job history, pins and
historical D4 edges, honors owner cancellation at step boundaries and resumes
after restart. A missing or altered reverse-index definition stays refused at
startup until EPIC-005's verified restore.

The shared Reader separates Evidence from a keyboard-operable Links tab with
Authored references, scoped Backlinks and an honest empty Suggestions section,
behind `capabilities.features.backlinks`; `/related` stays catalogued as not
ready. The operations have HTTP, native and desktop-facade parity.

On the final candidate these passed:
- the canonical gate, frontend build equality, and the desktop race and vet run;
- the focused persistence specs, including real SQL-only reverse-index content
  divergence (C06 contribution), key-collision damage, missing search rows and
  restart rollback;
- the public HTTP and CLI end-to-end tests;
- the Chrome Links driver, including delayed navigation after a context change.

Seeded grants and lifecycle rows are not production transitions; TASK-005
repeats them. Native Links navigation and copied links remain with TASK-004-05,
and the two-project C06 gate with TASK-004-06. The
[backlink evidence record](../../testing/backlinks.md) describes the executed
checks and their limits.
