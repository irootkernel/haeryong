## Delivered result

Review is an explicit owner action on one complete immutable directory version. Start,
complete, reopen and clear follow the registry's transition table; completion time is
server-assigned and a no-op or receipt replay preserves it. Opening or scrolling pages,
visiting every page, AI assessment and generated-frame messages never change Review, and
completing v3 leaves v4 Unreviewed while the old completion and history survive. State,
append-only history, the redacted audit/outbox event and the receipt commit in one
transaction at schema revision 10. A stale write returns 412 with the current validator,
malformed controls 400 and a reconciling receipt 409 OPERATION_RECONCILIATION_REQUIRED.
Review and its cursor history are owner-only; scoped document summaries carry nulls and
event batches mask hidden Review events.

GET/PUT `/versions/{id}/review`, GET `/versions/{id}/review/history`, the owner-only
`review` document-list filter and the optional document summary fields are additive
provisional contracts behind `capabilities.features.review`. The CLI adds `review show`,
`review history` and `review set`, keeping the original operation ID and preconditions
through uncertain outcomes. Browser, native and desktop clients share these operations.
The Reader's ReviewControl shows state, actions and history; Home lists continued and
updated-since-review documents with exact version links; and Versions reads each version's
own Review and defaults to the last still-Reviewed version against latest unless a pair
is chosen.
