# TASK-005-05: Implement coherent backup, portability export and protected restore

## Outcome

Back up original user data and referenced content, export exact anchored records for portability, and restore without reviving credentials, stale authority or external work.

## Inputs

- [operations/backup-recovery.md](../../operations/backup-recovery.md)
- [data-model.md](../../data-model.md)
- [contracts/cli.md](../../contracts/cli.md)

## Implementation work

1. Use EPIC-002 generic local jobs to snapshot the DB and pin the full transitive set of referenced immutable content/source objects while copying. Produce a coherent private local backup with an inventory, checksums and completed-copy/durability validation.
2. Restore into staging under local control. Rotate runtime_generation/auth_epoch/stream_epoch as specified, invalidate restored device tokens and let the owner review restored source/provider, exposure and automation preferences before affected external or destructive work resumes. Use labelled stored-but-disabled configuration for future exposure/automation capabilities; EPIC-007/009 repeat the guards with their production workflows.
3. Preserve generic uncertain-operation/receipt status and demonstrate stale snapshot ambiguity with a labeled synthetic external-result record. EPIC-006 adds actual provider-attempt reconciliation; this task must not depend on its future schema or runtime.
4. Add the owner-authorized CLI export plan/create/verify path: stream complete directory trees with exact file bytes, names, subdirectories, empty directories and recorded links, plus selected exact version/page-anchored personal/relationship metadata. Preserve ordinary imported attachments and source files already inside the selected directory; exclude separately retained source snapshots unless the owner chooses them. Do not flatten HTML, force a filename/manifest, impose export size/count caps or promise general cross-library personal-state merge.
5. Keep encryption optional for an owner-chosen export. If enabled, use an established format and verify the chosen round trip and wrong/missing-key error; routine private local backup does not require a portable key-management or replacement-host recovery subsystem.

## Required deliverables

- Local backup/restore/export CLI and shared UI instructions identifying this as host-local portability work. The original-directory package download remains the shared browser/Wails action; opt-in personal-record export does not claim an unimplemented remote export endpoint.
- Snapshot/object-pin coordinator and recovery fixtures.
- Portable export inventory, identity/anchor/hash verification and declared dependency/tombstone limitations.
- Documented local backup layout and checksum verification; optional encryption usage only where implemented.
