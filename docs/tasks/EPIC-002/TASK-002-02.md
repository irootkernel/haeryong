## Implementation work

1. Create the current project/document/directory-version/file/page/region/evidence/config schema plus operation receipts keyed by principal_id and operation_id, mutable resource revisions, transactional outbox/events with stream_epoch and sequence, and minimal durable local jobs with attempt_generation. Page identity is (version_id, page_path); optional region identity is (version_id, page_path, region_id), without cross-page slug collisions.
2. Implement streamed immutable object staging/finalization, cursor-based file inventory, resumable upload records, content-object references, active read sets and staging/backup pin primitives. Follow the [EPIC-002 slices](../../epics/EPIC-002.md#internal-implementation-slices): minimum safe pins/adoption and durable atomic publication precede resume/abandon and other upload purposes; no slice bypasses this Task's completion checks. Define job status/cancel and explicit local recovery semantics for non-provider work. Memory and transaction working batches may be finite without becoming total input-size, file-count or directory-depth caps.
3. Enforce transaction/connection and filesystem durability rules from architecture, data-model, package import and backup/recovery contracts; the schema registry owns wire shapes, not the fsync protocol. Use only tables needed for these delivered foundations; provider_attempts and external reconciliation extend them in EPIC-006.

## Import and transfer handoff

Use the frozen import-workflow contract for distinct request receipts, same-checkpoint seal-job coalescing and coupled cancel/abandon state. Prove the ledger/fence/pin slice with labelled fixtures here; TASK-002-04/05 add real sealing, publication and CLI transport. Cancelling a seal retains bytes, and no worker can finalize after its cancellation/abandon fence. A completed 202 receipt is a durable response, not a completed import. Caller-side pre-dispatch journals are separate from server receipts.
