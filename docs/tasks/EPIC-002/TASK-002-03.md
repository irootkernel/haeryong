# TASK-002-03: Implement local bootstrap and authenticated API sessions

## Outcome

Carry the proven pairing/session design into production service middleware without opening remote ingress yet.

## Inputs

- [contracts/authentication.md](../../contracts/authentication.md)
- [contracts/http-api.md](../../contracts/http-api.md)
- [operations/security.md](../../operations/security.md)

## Implementation work

1. Implement first local bootstrap, trusted-owner device approval/rejection and per-device bearer sessions for the same application listener. POST /auth/pairings/{id}/reject uses the authorized owner/bootstrap context and operation receipt; rejection is terminal and an approve/reject race cannot yield two successful decisions. Local and remote trusted host clients remember tokens in origin-local localStorage by default; expiry and memory-only storage are optional.
2. Authenticate the current token before private handlers and operation-receipt replay. Preserve single-use pairing, safe endpoint/return handling and the separation between the trusted host and generated frames.
3. Implement device list/revoke and authenticated event/receipt/job interfaces on the EPIC-002 foundations. Recheck current authorization before protected delivery; pass no management token to generated content.
4. Let every paired owner device manage the library and approve another device. Use ordinary impact preview/confirmation for destructive actions, exposure or source expansion; do not introduce a separate administrator or plan-grant system.

## Required deliverables

- internal/security/session.
- internal/adapters/http/auth.
- local control endpoint.
