# TASK-002-04: Implement atomic directory import and publication

## Outcome

Import a selected result directory, ZIP or single HTML file into one immutable directory version with deterministic byte identity and atomic receipts. No hand-authored manifest, file inventory, landing page, source metadata, file-type whitelist or size/count/depth quota is required.

## Inputs

- [Canonical import/transfer contract](../../contracts/import-workflow.md)

- [contracts/package.md](../../contracts/package.md)
- [data-model.md](../../data-model.md)
- [contracts/http-api.md](../../contracts/http-api.md)

## Implementation work

1. Stream files and typed directory entries into private resumable staging, derive metadata and canonical UTF-8 inventory identity, and validate actual paths, archive corruption and digests. Preserve every selected file, Unicode name, represented subdirectory/empty directory and supported link entry; ordinary files named manifest.json are content unless explicitly supplied as Haeryong metadata. Do not reject missing declarations or unsupported preview formats, and do not dereference links outside the selected tree.
2. Finalize and durably flush immutable payload under staging pins, then atomically publish metadata, principal-scoped operation receipt and outbox event/resource revisions.
3. Authenticate first, replay a matching completed operation before reevaluating its original stale precondition, and apply current authorization to replay output. Changed semantic preconditions or payload under the same operation ID conflict. Preserve ordinary relative/external hrefs and unresolved optional relationship metadata without fabricated resolved edges; normal JavaScript, modules, arbitrary attachments and missing source/region metadata do not invalidate a directory.
4. Follow the [EPIC-002 slices](../../epics/EPIC-002.md#internal-implementation-slices): establish the safe single-session publication path, then interruption/resume and explicit abandon before completing the remaining upload purposes. Show byte/file progress, cancellation and resumable incomplete staging. Above-former-limit fixtures must succeed on recorded adequate resources. Actual disk/I/O/resource failure never publishes partial content, silently truncates files or skips entries.

## Grok contract cases at this feature

Implement the frozen purpose/action target rules, explicit document_id and optional low-level base capture at the first POST /imports reservation. Normal clients send their pre-transfer base, which must still conflict if another publication wins during upload. Verify IMMUTABLE_VERSION_CONFLICT separately from stale-base and operation-key conflicts. Exercise upload_seal cancel versus abandon, same-checkpoint new completion keys linking one job, and retained-byte re-verification with new completion jobs. Reuse TASK-002-02's ledger/pin foundations; do not build a second coordinator.

Accept input from another volume by copying/streaming to destination-filesystem staging, verifying/flushing it, then finalizing on that same filesystem. Inject a cross-filesystem final-rename failure and verify no partial publication; do not turn the staging constraint into an input-volume ban. UI and final CLI orchestration are not claimed by backend tests.
