Complete user-visible manual maintenance with bounded update/new-document proposals and transparent results.

## Implementation work

1. Connect an explicitly selected content finding to authorized draft generation through POST /generations with finding_id, expected_finding_revision, intent:draft and the existing authorized scope/budget. The action creates a draft workflow; selecting a finding never silently approves an overlay or publishes content.
2. Show coverage/evidence/applied/blocked/rejected/unknown counts and affected Reviewed versions.
3. Implement draft preview, rejection and replacement in the shared Maintenance UI. PATCH /drafts/{id} with If-Match and action:reject applies only to preparing/ready drafts and fences linked job result application; action:replace uses a sealed upload on a ready draft and creates a revision preserving the captured base/history before validation. Publish remains a separate explicit POST /drafts/{id}/publish that creates a new version with pinned references and old user history intact. Repeat the actual Maintenance flow on the supported mobile viewports now that the feature exists.
4. Close Stage B only after the recorded relationship/freshness corpus passes its quality gate. Exercise disabled/propose/auto overlay modes, pinned/rejected decisions and explicit draft publication separately; no score transfers Reviewed.

## Required deliverables

- draft generation from proposals.
- full Maintenance report.
- Stage B evidence.
