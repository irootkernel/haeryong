# TASK-001-05: Validate subscription adapter and exact source reads

## Outcome

Establish a supported real subscription AI path, exact-source citations and honest provider permission behavior before promising live Q&A.

## Inputs

- [contracts/ai-adapter.md](../../contracts/ai-adapter.md)
- [contracts/source-access.md](../../contracts/source-access.md)
- [references.md](../../references.md)

## Environment prerequisites

- A supported account on the chosen test host and approved nonsensitive source/disclosure scope.

## Scope of the early gate

All T-001-05 checks below together form the single G-AI closing list. Require the actual supported account and one successful real cited question; a fake provider cannot replace them. Use a thin real-adapter harness for missing source, cancellation, authentication/quota error normalization and interrupted/unknown-outcome reporting, identifying observed versus injected transport failures. Do not exhaust a paid allowance or modify a shared login merely to provoke an error. The harness must preserve uncertainty and avoid blind redispatch, but full persisted provider recovery belongs to EPIC-006. Multi-page generation/value is TASK-001-07; production directory import/export is EPIC-002 onward. Their absence here is an explicit non-claim, not another G-AI blocker.

## Implementation work

1. Complete the TASK-001-01 deployment eligibility preflight and record the exact provider binary/version, supported authentication/billing mode and actual input-observation or post-hoc path. Test run-local environment precedence before dispatch; do not rewrite global settings, clear shared credentials or force a logout to obtain the intended mode.
2. Run one real cited fixture question over approved source bytes. Record each citation basis as observed_input only when the attempt has an input observation, with input_origin daemon_supplied or native_observed; a captured source read alone does not establish what the provider received. A later exact cited-source check uses posthoc_verified and can support claim review without claiming observed original inputs or automatic semantic correctness. Existing external agents use the owner's normal environment and existing tools/configuration. For managed calls, document actual reads, submissions and provider permissions; do not describe application scope as an OS sandbox.
3. Remember project/provider permission for subsequent reads in that scope. Confirm a new source scope through the normal owner flow, capture same-byte revision evidence, and exercise auth/quota failure, cancellation and uncertain outcomes without copying credentials into packages or logs.

## Required deliverables

- spikes/provider-source proof.
- G-AI eligibility/version record, actual permission/source-read observations and citation basis with any linked attempt input observation or later verification record.
- Source-retention and adapter ADR with the exact thin-harness scope, observed/injected error evidence and later production regression owners.

## Observable completion and tests

- [ ] T-001-05-01: Cited source matches the captured bytes/revision; concurrent file changes cannot produce a false exact-revision claim. observed_input requires a linked attempt input observation and correct input_origin; posthoc_verified cannot be displayed as evidence that those bytes were original provider inputs.
- [ ] T-001-05-02: The managed adapter respects remembered project/provider choices, reports its actual permission limits and asks only when the owner expands scope; normal external-agent tools are usable.
- [ ] T-001-05-03: Current eligibility and one real integration proof pass for the chosen baseline. Effective auth/billing mode and a working evidence path are recorded for the actual version; unconfirmed mode never silently dispatches through API billing. Auth/quota/cancel failures and interrupted/unknown outcomes are visible in the thin harness without blind retry; distinguish live observations from deliberately injected faults. Owner global environment/configuration/shared login remains unchanged by managed-mode checks.

## Excluded work

No OS worker jail, generic connector permission system or blanket disabling of existing agent hooks/plugins is required. Do not commit provider credentials or unapproved private source.
