# TASK-001-03: Validate pairing and private ingress design

## Outcome

Prove convenient remembered access for one owner across local and private remote devices, with generated pages kept outside the host's authenticated session.

## Inputs

- [contracts/authentication.md](../../contracts/authentication.md)
- [contracts/http-api.md](../../contracts/http-api.md)
- [operations/security.md](../../operations/security.md)

## Environment prerequisites

- An available local host, a second test client and an approved private remote route. A private HTTPS proxy may forward to the same application listener; no production network enrollment is implied.

## Implementation work

1. Prove first local bootstrap, approval of the next device by an already trusted owner device, single-use redemption and revocation using fixture data. Use the same configurable application listener, default 127.0.0.1:9270, for a private HTTPS proxy when chosen.
2. Use per-device bearer tokens for both local and remote hosts. Store them in the trusted host origin's localStorage by default until revoked; offer explicit expiry or memory-only storage. Reload and ordinary app restarts preserve a remembered device without another pairing ceremony.
3. Verify authenticated private API/assets/events/downloads, safe login returns and simple endpoint/Origin handling. Generated frames receive no management bearer, host storage access or approval capability. A paired owner can manage devices and confirm impactful settings through the normal owner flow.

## Required deliverables

- spikes/auth-ingress fixture.
- G-AUTH evidence record for pairing, remembered use and revocation.
- Authentication ADR with the chosen private route and actual tested clients.

## Observable completion and tests

- [ ] T-001-03-01: X03: concurrent redemption yields at most one device token; owner approve/reject races have one authoritative terminal decision and rejected requests cannot redeem. A pending/polling client cannot approve its own request.
- [ ] T-001-03-02: X04: local and remote paired devices survive reload with remembered bearer access; explicit expiry, memory-only mode and revocation behave as configured, and generated frames cannot read the host token.
- [ ] T-001-03-03: Invalid or revoked tokens stop private data/events; ordinary owner confirmation handles device/exposure changes without an extra permission tier.

Supplemental ownership: X03, X04 in [contract cases](../../testing/contract-cases.md). Initial proof is required at the owning feature; listed later tasks repeat the applicable regression.

## Excluded work

Do not modify the owner production network. This is a small one-owner authentication proof; it does not require a second listener, a cookie subsystem or repeated pairing for remembered devices.
