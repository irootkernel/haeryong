# TASK-001-02: Prove headless stack and native companion

## Outcome

Validate a real pinned Go/Wails/frontend/SQLite combination while keeping headless builds free of GUI dependencies.

## Inputs

- [architecture.md](../../architecture.md)
- [data-model.md](../../data-model.md)
- [operations/deployment.md](../../operations/deployment.md)

## Environment prerequisites

- Available primary host for Wails and an actual headless run without GUI dependencies. Record versions. This early spike does not require the full release matrix; retain the initial deployment targets and verify their advertised build/workflow support before release.

## Implementation work

1. Build a minimal headless HTTP service and independent Wails client using isolated fixtures; verify both attach to the same service and desktop exit leaves it alive.
2. Exercise SQLite transactions/restart, snapshot/backup consistency and the X09 Korean/code seed queries on the selected available host. Compare candidate tokenization behavior for short Hangul, spacing, snake_case, camelCase and symbols before selecting the driver.
3. Record exact toolchain/platform versions, measured query failures and module separation. Choose the driver/indexing baseline from this evidence rather than capability assumptions.

## Required deliverables

- Stack spike and headless/native build evidence.
- Toolchain/driver decision with initial Korean/code query worksheet.
- Snapshot and transaction consistency observations.

## Observable completion and tests

- [ ] T-001-02-01: Headless binary runs without graphical session or Wails runtime.
- [ ] T-001-02-02: Closing/crashing the native client leaves fixture service available.
- [ ] T-001-02-03: Driver capabilities and backup read consistency are demonstrated on declared test hosts.
- [ ] T-001-02-04: X09 records expected/observed short-Hangul, spacing and code-symbol results before driver/tokenizer selection; unsupported query cases remain explicit.
