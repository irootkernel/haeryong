# TASK-006-05: Implement region-aware source-grounded questions

## Outcome

Connect host Ask UI to captured display state, exact source mode and validated answer citations.

## Inputs

- [contracts/http-api.md](../../contracts/http-api.md)
- [contracts/ai-adapter.md](../../contracts/ai-adapter.md)
- [ui/screens.md](../../ui/screens.md)
- [testing/knowledge-quality.md](../../testing/knowledge-quality.md)

## Implementation work

1. Capture exact version/page_path, optional page-local region, query/fragment, selected context and chosen source mode before dispatch. Stage large serialized context automatically under context_ref without fixed author field-count, character-count, enum-count or 4 KiB caps; preserve its identity across page navigation and submit.
2. Present remembered project/provider/disclosure choices and source_mode_default, initially pinned, while permitting an explicit current override for this question. Changing the default through the project configuration plan affects future selection, never a captured question; require explicit submit.
3. Validate returned evidence IDs/revisions and persist final/partial/error states. Display observed_input only with the linked attempt input observation and input_origin; label a later exact cited-source check posthoc_verified. Later verification can aid claim review without asserting that original provider inputs were observed or that reference resolution proves the answer.
4. Evaluate answer support, missing-evidence abstention and observation/interpretation labels against the knowledge-quality corpus; syntactically valid citation IDs alone are insufficient.

## Required deliverables

- question/answer service.
- Ask context UI.
- citation validation fixtures.

- [ ] T-006-05-01: Pinned/current mode never silently swaps targets; remembered defaults reduce repeated setup while an explicit override and captured question scope survive navigation and later preference changes.
