# TASK-006-02: Implement configured source integration and selected snapshots

## Outcome

Provide exact pinned/current evidence and selected snapshots with remembered owner source/provider choices and explicit remote-source limitations.

## Inputs

- [contracts/source-access.md](../../contracts/source-access.md)
- [data-model.md](../../data-model.md)

## Implementation work

1. Extend the EPIC-004 reader with managed-AI source integration, captured revision/read/diff operations and inspectable read results. A broker is optional; suitable provider-native tools may be used. Link observed_input citations to an actual attempt input observation and input_origin daemon_supplied or native_observed. A captured read by itself proves only that read; a later exact cited-source verification uses posthoc_verified and cannot reconstruct unobserved original provider inputs. Existing external agents continue to use the owner's normal tools and environment.
2. Capture only the selected snapshots, retaining source intent, same-byte hashes and active job read-set pins; reference_only versus selected_snapshot is independent of available/unavailable/denied and of citation basis. Keep later verification records separate from original input observations; optional verification does not block raw directory ingestion or retained reading.
3. Remember project/provider permission and disclose the managed adapter's actual provider/tool settings. Confirm new source/provider scope through the ordinary owner flow, then reuse that choice without per-read prompts. Recheck revocation for further managed reads/submissions and do not claim an OS boundary the adapter does not enforce.
