# TASK-007-02: Complete browser pairing and session management UX

## Outcome

Make first pairing, remembered everyday access and per-device revocation convenient for the owner on local and private remote browsers.

## Inputs

- [ui/screens.md](../../ui/screens.md)
- [contracts/authentication.md](../../contracts/authentication.md)
- [operations/security.md](../../operations/security.md)

## Implementation work

1. Complete compare-code, trusted-device approval/rejection, single-use redemption and safe login-return UI over the existing pairing primitives. The first owner device uses local bootstrap; an already trusted owner device can approve or reject the next. Rejection calls POST /auth/pairings/{id}/reject and polling displays rejected. Stop waiting only stops this client's polling and discards its pending secret; it does not promise server-side cancellation.
2. Expose the device list/revoke UI and the default remembered bearer in host-origin localStorage for local and remote access. Offer optional expiry or memory-only sessions and use authenticated fetch for events/downloads; ordinary reload does not ask for pairing again.
3. Re-run X03/X04 on the chosen private route and an available second device, including reopening a copied exact-version link and revoking an active event connection.
4. Use the same owner session for device/library management and normal impact confirmations for destructive settings, exposure and new source scopes. Generated frames receive no bearer and cannot approve or initiate these actions.

## Required deliverables

- Connect and Devices/Sessions UI.
- Remembered bearer storage and explicit expiry/memory-only controls.
- First-pair, reopen and revoke tests on the chosen private route.

## Observable completion and tests

- [ ] T-007-02-01: An unpaired client gets no private data/assets/events; a pending request cannot approve itself.
- [ ] T-007-02-02: A remembered local or remote device reopens after reload without pairing again, and revocation blocks further delivery and mutation.
- [ ] T-007-02-03: Duplicate/expired redemption and unsafe return routes fail; rejection prevents redemption, approve/reject races show the authoritative result, and Stop waiting makes no server-cancellation claim. Optional expiry or memory-only mode clears access as configured.

Supplemental ownership: X03, X04 in [contract cases](../../testing/contract-cases.md). Initial proof is required at the owning feature; listed later tasks repeat the applicable regression.
