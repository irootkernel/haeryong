# TASK-007-03: Complete mobile/tablet workflow parity

## Outcome

Implement responsive reading, context and explicit owner controls for the owner's actual mobile browser.

## Inputs

- [ui/design-system.md](../../ui/design-system.md)
- [ui/wireframes.md](../../ui/wireframes.md)
- [ui/flows.md](../../ui/flows.md)

## Environment prerequisites and completion scope

Select and record one owner-provided physical phone or tablet on the private route for this Task's complete workflow proof, normally reusing the actual iOS/iPadOS Safari device from G-VIEW. Its absence blocks this Task; emulation is not a substitute. Other agreed P-11 mobile environments remain release obligations and must be tested before their support is claimed. They do not add hidden environments to this Task's closing set, and leaving one untested is not permission to remove it from the release plan. TASK-007-06 integrates the selected Stage A setup; EPIC-010 completes the agreed release matrix.

## Implementation work

1. Adapt directory page/file navigation and source/notes/Ask/Links panels to full-height sheets and tablet overlay. Load requested pages/assets on demand; a large directory must not require fetching all files before reading its first page.
2. Make touch/keyboard/text scaling/landscape and virtual keyboard safe.
3. Keep explicit personal review and lifecycle confirmation outside generated frame.
4. Repeat shared import/download controls on the actual private mobile browser. Exercise its supported directory/ZIP/file selector, cancellation/resume, authenticated streaming destination and concrete fallback for unavailable filesystem APIs; preserve original files without inventing a per-device product content ceiling.

## Required deliverables

- mobile Reader/Context sheets.
- responsive Library states and capability-disabled Maintenance shell. Full finding/action responsiveness is owned and repeated in EPIC-008 after those features exist.
- device capture set.

## Observable completion and tests

- [ ] T-007-03-01: X19/X20: On the recorded available phone or tablet, the owner can search, move among directory pages, select a page-local region, inspect evidence, follow an exact page link, operate useful JavaScript, transfer large context, ask, save a page-exact note and explicitly mark the entire intended version Reviewed.
- [ ] T-007-03-02: Check portrait/landscape, text scaling and virtual keyboard behavior on the actual selected device. Recheck the [design-system touch, contrast and focus criteria](../../ui/design-system.md#accessibility-requirements-for-this-project), including 44x44 CSS px targets, measured text contrast, visible focus and sheet focus return; link the TASK-003-06 baseline and record concrete failures. The environment section above governs this Task's closing set. Record tested versus pending iOS/iPadOS Safari and Android Chrome support separately; the remaining agreed targets stay assigned to release verification, not silently dropped or treated as extra early blockers.
- [ ] T-007-03-03: Browser flows need no desktop runtime and distinguish provider unavailable from daemon disconnected. X18 remote UI regression preserves represented selected import/download paths and bytes through the actual supported picker/transport. Record FileList empty-directory limitations and prove an available entry-aware/native/CLI or ZIP route includes directory entries for whole-tree fidelity, with explicit cancellation/resume and destination limitations.

Supplemental ownership: X02, X18, X19, X20 in [contract cases](../../testing/contract-cases.md). Initial proof is required at the owning feature; listed later tasks repeat the applicable regression.

## Excluded work

No native mobile app, offline caching or imitation of desktop terminal UI.
