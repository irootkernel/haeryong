# TASK-007-04: Implement multi-device reconciliation and conflict UI

## Outcome

Handle simultaneous owner edits and suspended mobile connections without false save or duplicate work.

## Inputs

- [contracts/http-api.md](../../contracts/http-api.md)
- [contracts/jobs-events.md](../../contracts/jobs-events.md)
- [ui/screens.md](../../ui/screens.md)

## Implementation work

1. Persist operation IDs in pending in-memory interaction state and query receipts before retry.
2. On reconnect fetch server-confirmed note/review/job revisions and resync expired event cursor. Reconcile reader-preference, the version last-opened pointer and each page-position as independent resources using only that resource's ETag; scrolling on one page must not move the pointer or overwrite another page's position.
3. Provide comparison/reload path for stale edits without losing unsaved draft text.
4. On changed stream_epoch or expired cursor, discard incremental assumptions and fetch authorized full state; preserve unresolved local intent without treating a request receipt as the current resource version.

## Required deliverables

- revision-aware client mutation layer.
- conflict/unsaved UI.
- mobile reconnect tests.

## Observable completion and tests

- [ ] T-007-04-01: A stale phone note/review write cannot overwrite a desktop update silently. Reconnecting reader preferences and per-page positions respect their independent revisions; two pages can save positions without a shared-version ETag conflict, while a stale write to the same resource is visibly reconciled.
- [ ] T-007-04-02: Suspending/closing browsers does not cancel durable jobs.
- [ ] T-007-04-03: Lost acknowledgement does not trigger a duplicate AI request or false Saved.

Supplemental ownership: X11, X12, X13 in [contract cases](../../testing/contract-cases.md). Initial proof is required at the owning feature; listed later tasks repeat the applicable regression.

No promised offline mutation synchronization or durable private browser cache.
