# TASK-007-01: Implement controlled private ingress and endpoint setup

## Outcome

Connect the existing one-owner service to the chosen private remote route while retaining the same application endpoint and a simple local recovery path.

## Inputs

- [operations/deployment.md](../../operations/deployment.md)
- [contracts/configuration.md](../../contracts/configuration.md)
- [contracts/authentication.md](../../contracts/authentication.md)

## Implementation work

1. Validate the configurable application listener, default 127.0.0.1:9270, and listener restart recovery. When a private HTTPS proxy is used, forward to this same listener and configured external origin.
2. Integrate the chosen private route with the same per-device bearer authentication used locally. Neither a second port nor a cookie-only remote session is required.
3. Inspect existing routes before applying network changes, present the normal owner impact confirmation for exposure changes and preserve local recovery if the endpoint fails.

## Required deliverables

- Endpoint setup/doctor checks.
- Private route and optional HTTPS proxy guidance.
- Reachability, remembered-auth and endpoint-conflict tests.

## Observable completion and tests

- [ ] T-007-01-01: An occupied configured port fails with useful recovery and no silent fallback or listener takeover.
- [ ] T-007-01-02: A private second device reaches the same authenticated service through the chosen route; existing unrelated routes remain intact.
- [ ] T-007-01-03: Configured external links and safe returns are correct, and forwarded network identity never substitutes for a valid owner bearer.

Supplemental ownership: X04 in [contract cases](../../testing/contract-cases.md). Initial proof is required at the owning feature; listed later tasks repeat the applicable regression.

## Excluded work

No automatic tailnet enrollment, Funnel or selection/provisioning of an always-on host.
