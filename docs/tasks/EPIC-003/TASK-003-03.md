# TASK-003-03: Implement the multi-page interactive Reader

## Outcome

Deliver a directory reader with multiple HTML pages, useful ordinary JavaScript, immutable version/page identity and a separate trusted management host.

## Inputs

- [contracts/viewer-protocol.md](../../contracts/viewer-protocol.md)
- [contracts/package.md](../../contracts/package.md)
- [contracts/http-api.md](../../contracts/http-api.md)
- [ui/screens.md](../../ui/screens.md)

## Evidence boundary

Implement the shared Reader now. Reuse the already passing TASK-001-04 Wails harness through the TASK-003-01 transport boundary for native-context regression; do not implement the production desktop companion, installer, tray or service discovery early. M14 here is a bounded contribution, not full scenario completion. TASK-003-05 and TASK-003-06 own the actual companion and integrated desktop proof. Production reader preferences/Continue/page positions belong here, unlike the earlier G-VIEW spike; durable Notes/Ask remain with their later owning features.

## Implementation work

1. Implement html_js_v1 without rewriting author code into a declarative format or flattening a directory into one file. Use render-bootstrap plus on-demand streamed/ranged files, preserving HTML/script/style/module/worker bytes and relative directory URL behavior. Bind cached wrappers/derivatives to immutable digests, page paths and renderer version; verify local input identity as content is served.
2. Bind sender/render/version/page/region channels. Transfer large serialized selection/context through automatic staged context_ref records and small control messages, without fixed author field-count, character-count, enum-count or total-state quotas. Internal JavaScript state remains unrestricted; Review, notes, questions and lifecycle controls remain in the trusted host.
3. Mount TASK-003-02's Import new version control in the Reader header with the exact document preselected and the base captured before transfer. Navigate all HTML pages with a page/file list, relative links, query/fragment state, browser history and direct page routes. An explicit page/deep link wins; Continue uses the version's last-opened pointer separately. Open without a page resolves the owner's preferred default, immutable supplied default, root index.html, sole HTML page, then Files/Pages. Implement reader-preference, reading-position and per-page page-position resources from the HTTP contract with their own ETags: opening/navigation updates the version pointer, scrolling saves only that page's position, and a default change neither republishes nor moves the pointer. Attachments remain accessible through supported preview or download, and absent regions fall back to page/version context.
4. Run X07/X16/X19/X20 with real prototype samples, modules/frameworks and focused host checks. Render requested files on demand without downloading every asset first. Document external dependencies honestly and recover from page/resource failures without mutating immutable content or personal completion.

## Required deliverables

- frontend Reader/IsolatedViewer.
- Server render and asset-loading path preserving package bytes, plus independent owner reader-preference, last-opened pointer and per-page position resources and UI.
- JavaScript/module loading, host-boundary and broken-page recovery tests.
