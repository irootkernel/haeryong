# ADR-009: Reference-first source retention and verified provider access

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R05 R08 R19 R20 R21 R38  
**Gate:** G-AI

## Source context

Revision 4: Source grounding; Subscription integration; Remote source boundaries. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Default to reference_only evidence with opt-in selected_snapshot retention. Directory import/viewing needs no source metadata or captured evidence; absent grounding remains unknown/unverified. A claim of source verification or a requested source-grounded answer still needs actual matching reads. Preserve exact source identity independently from capture status, runtime availability and bytes origin. Remember project/source/provider choices and automatically recheck their current scope without prompting per read. Keep same-byte evidence verification and a supported host-side provider route. Stream large source objects and inventory selected files incrementally; ordinary binary/large inputs are not rejected by a Haeryong size/type quota. Report a provider's real format/context limit separately, including which ranges or derived representations were actually submitted. Minimal read/revision/change observation may exist in EPIC-004 before the complete EPIC-006 integration.

## Alternatives and tradeoffs

A Git hash does not retain bytes and a phone connection does not mount a laptop repository. Excerpts/source-reader functions are useful options, while normal external agents may use the owner's existing configuration and tools. Record native provider permission behavior and best-effort limits accurately; a mandatory worker jail, neutral cwd or blanket plugin/hook ban is not required. externalSandbox does not create isolation.

## Consequences

Pinned retained evidence may remain available while the checkout is offline; missing bytes do not imply semantic outdatedness or a successful source-grounded answer. G-AI remains not_run and checks real supported subscription use, captured-read citations, remembered selections, no Haeryong-initiated source edits and interrupted attempt handling. No token copying, unsupported sign-in, silent paid-API switch or fixture provider may bypass the real integration condition.

## Validation and adoption

Apply [the detailed contract](../contracts/source-access.md) and record the actual evidence in the relevant EPIC-001 task before closing G-AI. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.
