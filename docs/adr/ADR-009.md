# ADR-009: Reference-first source retention and verified provider access

**Status:** accepted for the bounded TASK-001-05 provider/source baseline; future production mechanisms remain proposals
**Requirement IDs:** R05 R08 R19 R20 R21 R38  
**Gate:** G-AI

## Source context

Revision 4: Source grounding; Subscription integration; Remote source boundaries. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Default to reference_only evidence with opt-in selected_snapshot retention. Directory import/viewing needs no source metadata or captured evidence; absent grounding remains unknown/unverified. A claim of source verification or a requested source-grounded answer still needs actual matching reads. Preserve exact source identity independently from capture status, runtime availability and bytes origin. Remember project/source/provider choices and automatically recheck their current scope without prompting per read. Keep same-byte evidence verification and a supported host-side provider route. Stream large source objects and inventory selected files incrementally; ordinary binary/large inputs are not rejected by a Haeryong size/type quota. Report a provider's real format/context limit separately, including which ranges or derived representations were actually submitted. Minimal read/revision/change observation may exist in EPIC-004 before the complete EPIC-006 integration.

## Alternatives and tradeoffs

A Git hash does not retain bytes and a phone connection does not mount a laptop repository. Excerpts/source-reader functions are useful options, while normal external agents may use the owner's existing configuration and tools. Record native provider permission behavior and best-effort limits accurately; a mandatory worker jail, neutral cwd or blanket plugin/hook ban is not required. externalSandbox does not create isolation.

## Consequences

Pinned retained evidence may remain available while the checkout is offline; missing bytes do not imply semantic outdatedness or a successful source-grounded answer. Bounded G-AI records `pass` for real supported subscription use, captured-read citations, remembered selections, no Haeryong-initiated source edits and interrupted attempt handling. No token copying, unsupported sign-in, silent paid-API switch or fixture provider may bypass the real integration condition.

## Validation and adoption

The [detailed contract](../contracts/source-access.md) and [TASK-001-05 evidence](../testing/provider-source-spike.md) support this bounded acceptance after completed independent static confirmation. Future production adoption retains the owners and limits below. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.

## TASK-001-05 bounded implementation observation

The [provider/source experiment](../testing/provider-source-spike.md) and [runnable harness](../../spikes/provider-source/README.md) implement a thin local owner adapter. The thin baseline is accepted with bounded G-AI `pass` after the complete early closing list and independent static confirmation. Future production decisions and the owner-established source-retention limits remain unchanged.

Reference identity and selected captured bytes are separate. The earlier real completed question has exact accepted-input and native-echo evidence with `observed_input` / `daemon_supplied`; current read-only immutable-object checks verify the retained original bytes and citations without inventing a new input observation. No ambient native read or comprehension claim follows. Q5's source qualification and Q6's unverified literal serialized labels remain visible. Raw source/input/answer stay private; this observation does not enroll or promote a durable evidence package.

Current native startup observes the chosen subscription account/provider and inherited defaults, returned read-only/network-false permissions and ephemeral/version identity, then closes without a model turn. Child-only API credential exclusion preserves normal owner configuration, login, instructions, hooks and plugins. Application grants remember exact scope within a policy object; expansion requires an affirmative callback, without pretending to confine the whole owner process or persist production preferences.

The 75 injected checks cover missing/changed source, remembered/expanded permission, auth/quota/rate/capacity/context errors, cancellation acknowledgement versus terminal interruption, partial dispatch/unknown outcome, strict framing/deadlines and independent cleanup uncertainty. They are not observed live failures or actual OS process-containment evidence. Exclusive pre-dispatch intent prevents blind redispatch in this harness; it is not power-loss-durable provider recovery.

TASK-001-07 owns generation/value and the Haeryong-owned skill, TASK-001-06 owns contract integration, EPIC-004 owns production source observation, and EPIC-006 owns persistent provider recovery and later production regression. Ordinary result directories still need no source metadata, author manifest, index page, SDK or artificial content cap. No production service or adapter schema is frozen by this experiment.
