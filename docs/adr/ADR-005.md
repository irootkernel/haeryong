# ADR-005: Versioned HTTP API and owner pairing

**Status:** proposed; owner-pairing/private-ingress slice executed, production API and renderer delivery pending
**Requirement IDs:** R30 R31 R32 R33  
**Gate:** G-AUTH

## Source context

Revision 4: Authentication and browser security; Port and endpoint policy. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Propose /api/v1 HTTP JSON with authorized event delivery, exact mutation preconditions and operation receipts. Use one loopback listener at 127.0.0.1:9270 and optional private HTTPS proxy to it. Local and remote browsers use per-device revocable bearers stored in trusted-origin localStorage when Remember device is selected by default; memory-only use is optional. Idle/absolute expiry defaults to null. One owner authority covers reading and management, with explicit impact/confirmation for relevant actions and no separate administrative/consequential grants.

## Alternatives and tradeoffs

A tailnet IP, loopback address or forwarded header is not an owner session. Keep exact Host/Origin validation, private remote HTTPS and closed API CORS. Header bearer authentication avoids ambient cookie handling and a cookie-hostname reservation. Artifact execution stays outside the trusted token-bearing origin and native bridge. Tailscale embedding is optional.

## Consequences

Pair the first device through bootstrap; an existing owner session may approve another exact code. Remembered sessions survive reload, new tab, browser restart and normal daemon restart. Streaming imports/downloads keep management credentials in trusted transports and headers. Automatic version-scoped content delivery supplies normal multi-page and asset requests without exposing that bearer. Chunking, ranges, resumable transfer and cursor-based inventories prevent a fixed JSON body size or proxy buffer from becoming a hidden directory/file cap; verify the selected browser download handoff. G-AUTH checks that ordinary flow, revocation, optional expiry, private ingress, token separation and one-time restore invalidation. The one proposed port is configurable and unreserved; the gate remains not_run.

## Validation and adoption

Apply [the detailed contract](../contracts/authentication.md) and record the actual evidence in the relevant EPIC-001 task before closing G-AUTH. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.

Independent Task review and delegated Task acceptance are complete; the final two Low test-oracle corrections passed focused local checks. This is same-host private-route evidence; physical Safari renderer/storage evidence remains TASK-001-04. The fixture does not establish the production API, renderer/download transport or G-AUTH acceptance.
