# ADR-004: Shared reader-oriented frontend

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R28 R29 R35  
**Gate:** G-CONTRACT

## Source context

Revision 4: Shared web delivery and focused interface. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Propose React + TypeScript + Vite, shared components and a narrow platform transport adapter. Use the tri-panel reader on wide screens and sheets on mobile. A document opens its result directory with a page/folder navigator and one requested page at a time; root index or owner landing-page preference is optional. Preserve exact page/query/fragment context in history, copied links and page-local annotations. Paginate/virtualize large file lists and fetch files lazily; ordinary multi-page results do not require another document per HTML file.

## Alternatives and tradeoffs

Vue/Svelte are valid alternatives but do not justify duplicate browser/native domain rules. Graph-first home and IDE-style panels add complexity without satisfying the primary reading job.

## Consequences

Requires framework/version selection and actual touch/keyboard/state testing; text wireframes are not visual approval or prototype evidence.

## Validation and adoption

Apply [the detailed contract](../ui/README.md) and record the actual evidence in the relevant EPIC-001 task before closing G-CONTRACT. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.
