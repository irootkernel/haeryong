# ADR-008: Personal review and lifecycle as independent data

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R12 R13 R14 R15 R16 R17  
**Gate:** G-CONTRACT

## Source context

Revision 4: Personal review; Lifecycle/deletion; Backup and restore. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Keep exact-version personal review separate from freshness/lifecycle. A version represents the complete result directory: opening one page does not automatically mark its siblings or the whole version Reviewed. Page-local notes preserve exact version/page/region context. Use exact owner-confirmed impact plans or a confirmed timed-purge policy, with no separate elevated grant. Backups use coherent database snapshots and object pins, streaming complete directory inventories, all selected file types and referenced saved context without a total-byte/file-count ceiling. Application-managed restore invalidates old sessions once, reconciles remembered source/disclosure/automatic-action choices and preserves uncertain/orphan provider attempts.

## Alternatives and tradeoffs

Using Reviewed as an AI verification badge or applying it to new versions overstates user understanding. Generic age expiry may erase active records or shared assets.

## Consequences

Explicit state/history and a tested coherent private local backup with checksums are required. Encryption is optional for owner-selected export/shared copies, not a baseline recovery-key platform. Live purge is logical removal, not forensic erasure from storage history, backups or provider records. Full OS/VM rollback is not universally detectable. Failed migrations retain a verified recovery path. Normal restart preserves the sessions and selections established after restore.
