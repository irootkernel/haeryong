# ADR-006: Normal HTML/JavaScript outside the privileged host

**Status:** accepted for the bounded TASK-001-04 construction
**Requirement IDs:** R11 R30 R34  
**Gate:** G-VIEW

## Source context

Revision 4 supplied generated-HTML and Wails acceptance concerns; its unchanged text is in [sources](../sources/haeryong-concept-proposal-v4.md). The current owner direction trusts chosen generated/imported content for personal use and prioritizes ordinary web functionality. This ADR records that direction while leaving implementation evidence open.

## Decision proposal

Use one html_js_v1 profile with ordinary arbitrary author JavaScript, DOM, modules/frameworks, WebAssembly and network/CDN access under normal browser/CORS/permission behavior. Owner decision D-09 extends the concrete loading model to complete result directories with multiple HTML pages, nested/shared assets and no artificial HTML/package size, file-count, depth or type cap. Preserve per-version relative/root-relative URL semantics; lazy file retrieval replaces a full-package render envelope. Keep immutable directory bytes and any source provenance, and execute them outside the trusted host origin, stored credentials and Wails bridge. Reader-context messages carry no generic management privilege.

## Alternatives and tradeoffs

An opaque frame or separate render origin/context may provide the host boundary. Choose the simplest construction for each endpoint that supports real multi-page navigation, per-version root-relative/relative module/worker assets and normal library behavior across concurrent views. Wails and private-browser constructions may differ if they pass the same acceptance behavior. Do not silently remove functionality to fit an opaque sandbox. Flattening, forced inline-all output and a mutable global content-root mapping do not satisfy the directory contract. Account for inherited policy and verify the selected native sender/binding boundary. A JavaScript DSL, API allowlist, generated-script hash policy and universal zero-egress/RTC/DNS proof are outside this decision.

One loopback Go/API listener is not one browser origin: scheme, host and port determine browser origin, and a private proxy or renderer context can establish a different endpoint. D-10 authorizes the [additional private HTTPS port experiment](../operations/deployment.md#approved-additional-port-renderer-experiment) on the existing node name. Start there without making wildcard DNS/certificates, an owner domain, public exposure or another daemon mandatory. A shared origin plus version path prefix, Referer inference or an opaque frame is not accepted merely because a simple HTML page loads. Preserve exact concurrent root-relative fetch/module/worker behavior. Apply the [viewer mapping and lifecycle rules](../contracts/viewer-protocol.md#artifact-and-trusted-host-separation) for authored Service Worker replacement, origin reuse and storage across reload/restart/foreground. Same-version authored runtime/network responses remain distinct from verified stored-byte delivery. Record actual platform limits, but never label cross-version mixing as an accepted limitation.

Owner/agent bearers never enter artifact code or URLs. Each selected construction follows the normative [content delivery authority](../contracts/authentication.md#content-delivery-authority), including credential placement, observed closure, automatic renewal/recreation and current-access checks. Delivery lease expiry cannot abandon resumable uploads. Executable file previews stay in the renderer boundary. Bounded-memory reader-context transfer, any optional materialized-buffer fast path and Save/Ask adoption follow the [viewer protocol](../contracts/viewer-protocol.md#large-context-transfer-messages), without a generic privileged child-to-host API.

## Consequences

G-VIEW records `pass` against the entire [TASK-001-04 checklist](../tasks/EPIC-001/TASK-001-04.md#observable-completion-and-tests). Its required set is pinned macOS Wails, the selected primary browser and an actual agent-operated Aside browser on private HTTPS under the [2026-10-15 owner amendment](../decisions.md#owner-amendment-2026-10-15-agent-operated-private-browser-gate). Prove concurrent-version fetch/module/worker identity, delivery/navigation/context transport and focused host separation on the existing harness; record exact mappings, credentials, site/storage behavior, safe origin reuse and rollback before G-CONTRACT. Production preferred-default/Continue, durable Notes/Ask adoption and complete restore/import/export are later feature checks, not additional early requirements. Other agreed platforms stay in the release plan. Author context has no fixed content cap; host messages cannot authorize management, and a hung renderer has a documented recovery path without a universal CPU/process-containment promise.

## Selected TASK-001-04 construction

The [disposable viewer](../../spikes/viewer/README.md) uses one daemon with
trusted loopback API/UI on port 9270 and content-only listeners on 9272/9273.
The bounded private experiment maps HTTPS 9271 directly to HTTP 9270 and HTTPS
9272/9273 directly to the corresponding content listeners on the existing
Tailnet node. Existing Serve/Funnel entries are preserved; the new mappings
have no Funnel exposure. A synthetic HTTPS 9274 experiment forwarded to loopback 9284 with the internal
`/__renderer/origin-a/` prefix. Actual normal-TLS requests preserved prefix joining,
escaped slash/space and the external Host; two byte ranges and a redirect also
passed. Thus distinct external origins with internal prefixes are viable. The
selected direct upstreams retain the same external origin separation while
keeping trusted API policy separate from content-only route handlers. Actual agent-operated Aside private-browser observations are now recorded;
independent review and delegated acceptance remain required under the current
owner amendment.

Owner bearers stay header-only in the trusted host. Renderer handoff credentials
are separate, one-time POST values followed by HttpOnly narrow delivery cookies named for each delivery. Multiple
logical tabs of one version retain independent credentials; the content handler
uses only a currently authorized grant for its exact version/origin.
Cookies are shared across same-host ports, so each content read additionally
checks actual Host/Origin/Fetch Metadata and its pinned version, lease and current
owner. The actual sandboxed form POST can have `Origin: null`; only the scoped
one-time handoff accepts it. Management rejects it. An authored root Service
Worker can observe its own later handoff; the narrow renderer credential is not
an owner bearer. A persisted origin-to-version/inventory registry refuses
cross-version reassignment after restart. This registry must survive for as
long as browser storage at those origins can survive.

Browser downloads use an independent HttpOnly selected-object cookie on the
trusted download route and a direct Content-Disposition response. The route
checks its trusted sender context, current owner, immutable version/object and
progress lease. Native downloads retain their separate header credential and
stream to a file. Neither transport materializes a whole-file JavaScript Blob.
The selected primary Chrome construction launches the installed binary with
minimal arguments and an owned profile, attaches through loopback CDP and records
actual browser download events/destination bytes. The preserved earlier full local checker recorded download/close and remembered/active-daemon restart on its exact candidate. Current focused checks and explicit source comparisons carry only unaffected paths; they do not establish a new full-checker pass. The public checker now reopens the exact broken document, verifies its fresh binding/error, then explicitly selects a healthy page. Earlier default
Playwright launch failures remain retained; changing both launch and collection
does not establish their cause. The current owner amendment assigns the third early construction to Aside
private HTTPS. Its actual Chromium 153.0.8010.53 browser recorded direct UI and
streaming/lifecycle/storage-recovery observations without owner intervention.
The automatic report retains one failed popup relay, composed with a separate
actual unprivileged popup proof. The browser download UI destination remains
unverified after an Aside path-wait timeout; a separate incremental browser
ReadableStream into a temporary file completed with exact inventory bytes/digest
after authenticated renderer close. This does not claim production export or
constant browser buffering. Android remains untested in the later support matrix.

The pinned native construction serves trusted HTTP like TASK-001-02. A local
WKScriptMessageHandler guard validates `frameInfo.isMainFrame` and the actual
security origin before Wails' special `wails:` branch or raw dispatcher. The
public custom Transport invokes the real registered MessageProcessor bindings.
A fresh popup user-content controller removes native handlers. WebKit requires
the supplied popup configuration and rejects clearing its copied registered
scheme handler on this SDK; the supported candidate therefore denies every
`wails://` asset/runtime request in middleware. Trusted custom transport remains
independent of that scheme. The failed SDK experiments are retained as local
incident evidence and do not establish a passing boundary.

Read-before-rewrite A/B storage probes record actual localStorage, IndexedDB and
Cache behavior across reload, client restart and active-daemon restart. Chrome
retained all three locally. Wails UI process restart lost authored localStorage
and IndexedDB values while retaining Cache values; this is an observed limitation,
not a persistence guarantee or inferred WebKit cause. The daemon restart keeps
owner access and immutable origins while automatically recreating ephemeral
delivery. Current local and actual Aside private-browser results, including their limits, are indexed in
the [viewer experiment record](../testing/viewer-spike.md).

Rollback stops only the owned fixture/native processes and new foreground
Serve mappings, verifies existing routing entries against the captured baseline,
and retains private evidence according to the local retention policy. No
production data migration, dynamic origin allocator or new daemon is selected.
All required constructions and the original closing list have completed evidence
and independent confirmation; G-VIEW records `pass` for this bounded baseline.


## Current bounded correction

The current page channel supplies full binding/protocol/sequence in both context
transfer directions, validates current port/generation and pending reply identity,
and honors advertised credit. Temporary service context IO uses per-transfer
serialization so independent delivery progress and renewal do not wait behind an
uncapped context read or seal; current access is rechecked before acceptance and
seal completion. These corrections retain the selected origin/native construction.
The early temporary seal proves transport only; production purpose-bound upload
identities, durable adoption and pins remain with their later feature owners.
Current recovery controls preserve exact selection and distinguish authored
errors, ended owner access, failed original popup relay and separate observations.
At that correction checkpoint, selected review remained required; original
incomplete reviews and earlier execution limits remain preserved.


## Selection and transient recovery refinement

A registered renderer retains its exact requested selection before a page channel
is accepted; the latest complete accepted location then takes precedence. Reload,
Reopen and disposal share this selection. If config refresh fails before replacing
a renderer, its renewal generation is restored only while that same live view and
latest intent remain current. Closed, superseded, ended-owner or pagehidden views
stay invalidated. Natural timer and controlled-failure observations are distinct
from the earlier actual daemon restart proof.

The existing derived loader observes successful ordinary History pushState and
replaceState calls and current traversal events. It preserves native receiver,
arguments, returns and exceptions and does not propagate observer failures into
successful authored calls. This requires no compulsory author SDK or metadata and
does not change immutable authored bytes or origin/version assignment. Current
focused correction evidence composes with earlier unaffected full-checker rows;
it does not claim a fresh complete download/storage/restart run.


## Pathname lifetime correction and evidence scope

A different pathname invalidates the derived loader's previous port, generation
and pending context before announcing the new complete location. The host keeps
that exact requested selection and disposes the old page channel/context before
metadata lookup. Loaded/connect/ready messages share a fresh internal
announcement identity; stale metadata, candidates and connects cannot supersede
the newest location. An actual late old temporary seal may exist on the server
without authorizing an old ready reply or attachment to the new page. Current
three-construction proof checks that lifetime directly; earlier large-transfer
proof applies only to its unchanged byte/credit/digest mechanisms.

The original whole checker retains an unresolved native query-only Back failure
after actual trusted-document reload: the child restored about:blank. Its whole
runs remain failed and the cause is unknown; no platform certification, BFCache
explanation or repair is inferred. The pre-existing single closing list and
additional-case rule allow a distinct required-pathname subset, with actual
exact reload/logical-tab and stale-context proof, without claiming that extra
combination passed. General Back/Forward behavior and later obligations remain
unchanged. Earlier traversal evidence is carried only for its observed sequence.

The current required subset passed on pinned Wails, primary Chrome and actual
Aside private HTTPS and composes with explicitly unchanged earlier evidence.
The completed frozen-finding independent confirmation found no remaining
findings against the original fourteen criteria. G-VIEW records `pass` and this
ADR is accepted only for the bounded construction and retained evidence scope.
See the [complete current record](../testing/viewer-spike.md#independent-review-ordinal-3-pathname-correction)
for the original fourteen-criterion mapping, failed extras and retained limits.
