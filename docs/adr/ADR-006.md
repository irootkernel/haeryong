# ADR-006: Normal HTML/JavaScript outside the privileged host

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R11 R30 R34  
**Gate:** G-VIEW

## Source context

Revision 4 supplied generated-HTML and Wails acceptance concerns; its unchanged text is in [sources](../sources/haeryong-concept-proposal-v4.md). The current owner direction trusts chosen generated/imported content for personal use and prioritizes ordinary web functionality. This ADR records that direction while leaving implementation evidence open.

## Decision proposal

Use one html_js_v1 profile with ordinary arbitrary author JavaScript, DOM, modules/frameworks, WebAssembly and network/CDN access under normal browser/CORS/permission behavior. Owner decision D-09 extends the concrete loading model to complete result directories with multiple HTML pages, nested/shared assets and no artificial HTML/package size, file-count, depth or type cap. Preserve per-version relative/root-relative URL semantics; lazy file retrieval replaces a full-package render envelope. Keep immutable directory bytes and any source provenance, and execute them outside the trusted host origin, stored credentials and Wails bridge. Reader-context messages carry no generic management privilege.

## Alternatives and tradeoffs

An opaque frame or separate render origin/context may provide the host boundary. Choose the simplest construction for each endpoint that supports real multi-page navigation, per-version root-relative/relative module/worker assets and normal library behavior across concurrent views. Wails and private-browser constructions may differ if they pass the same acceptance behavior. Do not silently remove functionality to fit an opaque sandbox. Flattening, forced inline-all output and a mutable global content-root mapping do not satisfy the directory contract. Account for inherited policy and verify the selected native sender/binding boundary. A JavaScript DSL, API allowlist, generated-script hash policy and universal zero-egress/RTC/DNS proof are outside this decision.

One loopback Go/API listener is not one browser origin: scheme, host and port determine browser origin, and a private proxy or renderer context can establish a different endpoint. D-10 authorizes the [additional private HTTPS port experiment](../operations/deployment.md#approved-additional-port-renderer-experiment) on the existing node name. Start there without making wildcard DNS/certificates, an owner domain, public exposure or another daemon mandatory. A shared origin plus version path prefix, Referer inference or an opaque frame is not accepted merely because a simple HTML page loads. Preserve exact concurrent root-relative fetch/module/worker behavior. Apply the [viewer mapping and lifecycle rules](../contracts/viewer-protocol.md#artifact-and-trusted-host-separation) for authored Service Worker replacement, origin reuse and storage across reload/restart/foreground. Same-version authored runtime/network responses remain distinct from verified stored-byte delivery. Record actual platform limits, but never label cross-version mixing as an accepted limitation.

Owner/agent bearers never enter artifact code or URLs. Each selected construction follows the normative [content delivery authority](../contracts/authentication.md#content-delivery-authority), including credential placement, observed closure, automatic renewal/recreation and current-access checks. Delivery lease expiry cannot abandon resumable uploads. Executable file previews stay in the renderer boundary. Bounded-memory reader-context transfer, any optional materialized-buffer fast path and Save/Ask adoption follow the [viewer protocol](../contracts/viewer-protocol.md#large-context-transfer-messages), without a generic privileged child-to-host API.

## Consequences

G-VIEW remains not_run and closes only against the entire [TASK-001-04 checklist](../tasks/EPIC-001/TASK-001-04.md#observable-completion-and-tests). Its required set is pinned macOS Wails, the selected primary browser and one real iOS or iPadOS Safari device on private HTTPS. Prove concurrent-version fetch/module/worker identity, delivery/navigation/context transport and focused host separation on the existing harness; record exact mappings, credentials, site/storage behavior, safe origin reuse and rollback before G-CONTRACT. Production preferred-default/Continue, durable Notes/Ask adoption and complete restore/import/export are later feature checks, not additional early requirements. Other agreed platforms stay in the release plan. Author context has no fixed content cap; host messages cannot authorize management, and a hung renderer has a documented recovery path without a universal CPU/process-containment promise.

## Validation and adoption

Apply [the detailed contract](../contracts/viewer-protocol.md) and record the actual evidence in the relevant EPIC-001 task before closing G-VIEW. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.
