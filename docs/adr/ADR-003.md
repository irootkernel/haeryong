# ADR-003: Haeryong-owned skill and workflow-scoped agent sessions

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R18 R19 R21  
**Gate:** G-AI

## Source context

Revision 4: The skill belongs to Haeryong; Source access and AI actions. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Distribute one version-compatible generation/maintenance skill with the product. Aquarium and standalone agents use it in the owner's existing environment. Haeryong automatically issues workflow-scoped CLI/API sessions from the selected work. The skill accepts ordinary result directories with multiple HTML pages and related files; it does not demand a hand-written manifest, hashes, universal region declarations, inline-all output or a content size/count quota. Haeryong generates its inventory and integrates optional metadata.

## Alternatives and tradeoffs

An Aquarium-owned duplicate generation contract couples release ownership and makes standalone use diverge. A skill supplies workflow guidance; Haeryong enforces its own API scopes and reports the provider's actual permission-mode limits.

## Consequences

Verify installation and the selected provider route. Workflow sessions cannot author personal review, purge, approve devices or change policy. Source/project/provider choices are remembered rather than approved per read. Existing agent tools, instructions and hooks may remain in use; a worker jail and blanket tool disablement are not prerequisites. Application scopes do not sandbox an unrestricted process in the owner's account. Restore invalidates old agent sessions once; normal restarts retain valid new sessions.

## Validation and adoption

Apply [the detailed contract](../contracts/ai-adapter.md) and record the actual evidence in the relevant EPIC-001 task before closing G-AI. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.
