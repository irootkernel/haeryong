# ADR-007: Audited maintenance instead of historical rewriting

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R10 R22 R23 R24 R26  
**Gate:** G-CONTRACT

## Source context

Revision 4: AI-managed wiki maintenance; Freshness and historical truth. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Use captured scan inventories, separate structural/semantic coverage, evidence-backed overlays and explicit content drafts. Inventories enumerate full directory versions incrementally, and findings identify exact page paths and optional page-local regions. A large directory is valid even if a selected provider run examines only part of it; record examined/unexamined coverage without treating a processing budget as an import or file-count cap. Preserve user decisions and recheck current restrictions before application.

## Alternatives and tradeoffs

Automatically overwriting documents or treating every changed hash as outdated corrupts history. All-pairs AI linking is expensive and produces unsupported relations.

## Consequences

Needs durable jobs, typed findings, rejection fingerprints and conflict-safe undo. Provider unknown outcomes remain explicit rather than assumed exactly once.

## Validation and adoption

Apply [the detailed contract](../contracts/jobs-events.md) and record the actual evidence in the relevant EPIC-001 task before closing G-CONTRACT. Update this record to accepted only after the decision and evidence are reviewed. If a future implementation changes an invariant or owner direction, use a bounded change request rather than silently editing historical source text.
