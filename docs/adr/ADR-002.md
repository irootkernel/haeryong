# ADR-002: Immutable result directories and canonical page links

**Status:** proposed, not yet implementation-validated  
**Requirement IDs:** R02 R03 R04 R06 R07  
**Gate:** G-CONTRACT

## Source context

Revision 4: Explanation packages; Knowledge links and backlinks. The unchanged concept is in [sources](../sources/haeryong-concept-proposal-v4.md). This ADR elaborates the direction and must not be treated as an independent owner approval.

## Decision proposal

Under owner decision D-09, treat one AI result directory as one document and its complete immutable snapshot as a version. Accept ordinary directory/ZIP/standalone-HTML input with automatically generated inventory; multiple HTML pages and their assets need no manual manifest, fixed entrypoint or artificial byte/file-count/depth/type limit. Preserve exact relative UTF-8 paths and all selected files. Optional metadata enriches source grounding and wiki integration; missing metadata remains unknown/unverified and does not block import/viewing.

A page has identity (version_id, page_path), and an integrated region has identity (version_id, page_path, region_id). Canonical reader URLs preserve page path, artifact query/fragment and optional host region focus. Separate historical capture records from runtime source availability and current access authority. Keep authored directed edges canonical; derive backlinks and attach management overlays separately.

## Alternatives and tradeoffs

Overwriting HTML or storing independent backlink rows loses provenance and creates repair drift. Flattening a result into one HTML or dropping unsupported attachments breaks ordinary output and relative links. Automatic indexing and lazy file retrieval add storage/loader work but avoid author packaging bureaucracy. A graph database is unnecessary for the initial lookup/query scope.

## Consequences

Immutable objects need durable finalization before referencing DB commits, incrementally verified bytes on requested rendering/source use, garbage collection, backup pins and explicit target tombstones. Paginate inventories and stream imports, requested files, exports and backups without requiring total content in memory. Actual storage/platform errors remain explicit, with no silent truncation or invented infinite-resource guarantee. Latest navigation stays separate from pinned provenance. A storage hash detects mismatched packaged bytes; runtime network dependencies are not automatically captured provenance. The owner chooses which executable content to run, and a digest is not an OS security boundary.
