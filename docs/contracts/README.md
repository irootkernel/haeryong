# Contract index

**Contract family:** v1, proposed for freeze at TASK-001-06. Runtime schema 1.0 and API /api/v1 are separate from documentation bundle version 1.6.2. This personal developer-tool baseline manages complete result directories with multiple HTML pages, normal AI-authored HTML/JavaScript through html_js_v1, remembered per-device bearer sessions for one owner and ordinary impact confirmation. It imposes no artificial total-content or file-count limit and requires no author manifest. It does not claim compatibility with a deployed implementation or passing gate evidence.

The shared registry owns common enums, generic receipts, citation variants and coverage aggregation. It delegates exact transfer/import fields and composite-command behavior to import-workflow. Authentication owns content-delivery authority; package owns caller association and exact-path lookup. Other documents summarize and link those definitions instead of creating parallel rules. The [Grok reconciliation](../changes/2026-10-11-grok-reconciliation.md) records current ownership and D-10's private-renderer-port approval. G-VIEW and G-AI close against the full checklists in TASK-001-04 and TASK-001-05; longer contracts describe future product behavior rather than extra early gate conditions. After G-CONTRACT freeze, additive optional fields may be introduced within the recorded compatibility rules. Changing identity, permissions, required fields, error meanings or immutable digest rules requires an explicit runtime contract revision. Compatibility is directional: clients may ignore explicitly optional, nonauthority response fields; unknown state/action enums or authority-bearing meanings make the affected operation unavailable until understood. Requests/configuration reject unknown fields unless that field is explicitly an extensible authored/display payload. Unsupported required schema features or major versions return a typed error. An older service must not silently accept a newer client's required mutation semantics. /api/v1/capabilities advertises implemented features, runtime/stream generation and implemented html_js_v1 loader/runtime support; unavailable routes return FEATURE_NOT_READY, never simulated success.

Before each feature is implemented, its shared states, actions, request/response shape and client behavior must be concrete. The [schema registry](schema-registry.md), specialized contracts and [UI action mapping](../ui/screens.md) share those definitions; table names in the data model do not themselves freeze a complete database schema. TASK-001-06 must turn the selected normative shapes into executable schema/contract fixtures under the implementation tests/contracts area, record their digest and verify shared client representations. Machine-generated types are an implementation option, not a claim about files supplied here. In particular, the page-scoped host-message/context_ref and path-preserving streamed loader contracts, canonical UTF-8 inventory, resumable transfers, request fingerprints and compatibility examples need actual evidence before G-CONTRACT passes. Markdown completeness does not close G-STACK, G-AUTH, G-VIEW or G-AI.
