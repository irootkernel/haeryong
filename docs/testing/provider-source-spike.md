## Eligibility and version

The owner-selected personal Mac construction runs an owned Codex stdio child beside existing local ChatGPT authentication. Private browser clients read produced results; no remotely hosted inference, multi-user customer service, token sharing or public provider listener is introduced. Official [app-server authentication guidance](https://learn.chatgpt.com/docs/app-server#auth-endpoints) permits local/open-source integration, with a separate [Sign in with ChatGPT integration route](https://developers.openai.com/siwc/token-sharing-open-source). The applicability of this strictly local construction is a documented inference from that guidance, not a vendor statement naming Haeryong. App-server remains experimental; reconsider eligibility before changing deployment or billing scope.

The demonstrated binary/protocol is Codex CLI `0.162.1`. The managed argv selects the built-in OpenAI provider and inherits the owner's model and effort. Child-only API credential exclusion and native account/config checks establish the selected subscription route; an ambiguous account/provider/permission response blocks dispatch. API-key precedence with keys actually present in the native child was not tested. Forced login restrictions were not set because they can invalidate a shared login. No global setting or shared credential repair is part of the experiment.
