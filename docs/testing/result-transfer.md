## Original-directory download

`GET /api/v1/versions/{id}/package` streams a generated ZIP of the published inventory: exact paths, file bytes, represented empty directories and symlink text/type, without added service metadata. Owner authority or an exact project/version `package.export` scope is required; `version.read` alone does not grant export. Authority is renewed while reading and writing. Before body commitment errors use the canonical JSON registry; after commitment an error aborts the HTTP stream. Failed assembly does not finalize an archive. The inventory digest is not a digest of generated ZIP wire bytes.

The frontend streams the authenticated response into a real writable destination without a whole-body Blob. Completion requires clean stream EOF and successful destination close. Reader/write/close failures and cancellation produce an incomplete result. Replacement consent precedes destination acquisition. A dropped directory permits an explicit existing-file conflict decision, including an existing empty file. A save-picker handle cannot establish prior existence. File System Access has no atomic no-replace operation; consent covers a file appearing after an existence check. Unsupported transport displays its limitation and the supported CLI alternative.

Folder FileList selection represents files and implied parents, but cannot represent empty directories or symlinks. ZIP entries provide the whole-tree route. A case-insensitive host folder cannot supply distinct `Readme`/`README` files; ZIP entries can preserve both. Native system-save-dialog interaction is not established by headless automation. The actual host-write test uses a disposable Chrome profile with an explicit per-origin write-permission pre-grant, trusted host directory drop and real writable stream; this proves product destination writing, not the normal permission prompt or chooser UX.
