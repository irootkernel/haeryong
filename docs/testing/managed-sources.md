## Delivered behavior

The collector streams owner-selected Git/file bytes through the real immutable
object store. Git current resolves the selected reference once; pinned accepts
its exact revision or retained selected snapshot. Working-copy/files capture
exact per-file bytes without claiming an atomic whole-repository snapshot.
Capture, staged pending/result rows, source retention and actual provider-input
observations remain separate. A failed selection keeps every original unit,
actual reason and null target instead of reducing the denominator.

Normal Sources settings use the existing shared React revisioned
plan/confirm/commit flow, including remembered pinned/current default and nullable
provider default. A default provider does not grant source disclosure: empty
provider_ids denies. Current session/project/source/provider restrictions fence
further reads, submission and application without per-read prompts. Concrete
host-owned live profile/bootstrap and provider-auth paths are excluded from
managed collection, including opened aliases; ordinary filenames/extensions,
binary files and large source remain supported. No provider credential is read
or put into source evidence, browser content or diagnostics.

Reference-only standalone capture releases temporary bytes after completion.
An explicit byte read may reread its exact approved target and verify the old
hash; changed/missing bytes cannot inherit that identity. Selected snapshots
verify/read offline under current access. A metadata view is not_read_by_view,
not an actual input observation or content verification. Captured HTML/JavaScript
is delivered as an octet-stream attachment with nosniff, preserving its bytes
without executing it in the trusted host.

Trusted future semantic admission uses CaptureAndAdmit in one writer transaction
to finish capture, create its authorized queued job and attach exact input pins
before capture ownership ends. Selected-snapshot reference adoption and input
pin acquisition remain in that same transaction. A public job ID, a digest or a
ready metadata row grants no reference-only input attachment. Execution owners
remain through queued/running/unknown work and are released only by the existing
terminal/all-effects-definite rule. Version-context snapshot ownership joins
existing purge impact, cancellation, bounded cleanup and GC; project-only
snapshots and all independent same-hash owners remain separate and usable.
A purge with active/unknown/independent ownership reports its protected remainder.

Backup projects reference-only source owners as uncopied/unavailable, preserving
selection, digests, source-version/retention facts and uncertainty. It retains
actual bytes whenever independent payload/snapshot/result/other ownership needs
them, with the original strict required-object checks. Opt-in export includes
only separately retained source snapshots bound to that selected version.
Protected restore retains the normal source-policy review barrier and never
invents missing byte availability. Migration 15→16 is atomic with the existing
verified pre-migration recovery set; missing/altered DDL refuses startup. Legacy
hash-only captures gain no invented object/binding/observation.
