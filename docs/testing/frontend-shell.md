## Delivered boundary

- `frontend/`: React 19.3.0/TypeScript 7.0.2/Vite 8.3.4 shell (registry router, Korean copy per the R5 baseline and design-system vocabulary, CSS-variable theme), `HttpHaeryongClient` (same-origin `/api/v1` header bearer, `credentials:'omit'`, `redirect:'error'`), `NativeHaeryongClient` over a named-only `NativePort` (no arbitrary URL/path/method proxying; the real desktop binding is TASK-003-05), credential stores retaining the `haeryong.owner-session.v1` key, and the connection state machine (verified/degraded/incompatible/unauthenticated; checking only on initial/new-authority loading).
- Authority-era contract: the transport credential/era changes only on credential, library or runtime-generation boundaries. Routine same-authority rechecks keep the mounted screen (verified stays verified; degraded stays write-gated until success) and never invalidate in-flight writes. Uncertain writes keep the original K operation identity (Idempotency-Key + original If-Match for same-intent retry) or the natural `session_id` target, are reconciled via `GET /api/v1/operations/{id}` receipts or current session-list rereads, and late failures after logout/credential/library replacement never reinsert previous-owner pending intents. Logout clears this browser immediately; only an explicit success response or `SESSION_REVOKED` for the same credential is reported as a confirmed server revocation.
- Go: `internal/webassets` embeds the committed `dist` (built by `frontend/check_build.py`, which also records a deterministic input digest); `internal/adapters/http/auth` serves the shell on registry routes and `/assets/*` with `no-store`, extended `style-src 'self'` CSP, and server-side `haeryong-session-defaults` meta injection. The old embedded plain-HTML connect page and `/auth-client.js` route were removed. Canonical gates stay Node-free: the `internal/webassets` unit test recomputes the input digest and verifies every recorded file digest.
- Browser harness `internal/adapters/http/auth/browser/`: updated for the React shell (role/accessible-name queries, `[data-state]` service indicator, retained `window.pollCalls` technique, localStorage key, secret non-leak checks), fixture composed with the daemon's query routes plus an `--alias` trusted origin and monotonic synthetic clock across restarts, typed/redacted control-failure reasons, loopback fault proxy (api_version 2.0 / runtime-generation rewrite), lost-ack K-receipt recovery across disconnect/reconnect, recheck-stability (partial inputs across >2 intervals and visibility), keyboard and emulated-touch walkthroughs.

## C1 corrections carried into this candidate

Task Judge's C1 review found two required failure-path defects, both fixed here: (1) a successful 2xx response whose body read or JSON parse failed escaped as an unclassified error, so an uncertain decision write lost its K recovery identity — the transport now raises a typed `UncertainResponseError` (headers may have arrived and the server may have applied the write) which the controller records exactly like other uncertain outcomes, with authority-era discard and previous-owner reinsertion guards intact; the non-JSON error-status fallback remains honest. (2) `confirmRevokeResolved` only accepted row absence, but production session lists keep `revoked`/`expired` rows — a target row in state `revoked` now counts as confirmed completion, `active` stays unresolved, and `expired`/unknown states are never treated as proven revoked.

## C2 additional corrections

Three further required fixes from review: (3) `#openEvents` guarded the liveness recheck by the verification-run counter, so a routine same-authority recheck wrongly invalidated the still-current stream; the guard now uses subscription/controller lifecycle identity (current subscription + verified phase + unchanged authority), preserving the bounded backoff while stops, replacements and authority changes correctly suppress late closes. (4) Pending-intent recording read `capabilities.library_id` after awaiting, so an unverified mixed-library observation during a dispatched write could retag and then silently drop the original intent on recovery; the recovery scope captures the controller's confirmed library identity (`#libraryId`, advanced only on verified passes) at dispatch and never retags it. (5) Follow-through: the truncated-body browser case now proves the actual browser observation — the exact approval response is awaited before the click, its HTTP 200 status and positive Content-Length header are asserted to have reached the browser, `response.body()` is observed to reject on the truncated transfer, and only then the unknown outcome plus same-receipt recovery are asserted; the malformed-body and full-response-abort cases remain separate regressions.

## C3 dispatch-boundary correction

C2 review found that an owner approval callback could finish its pending-list lookup after the connection became incompatible, then send a new protected write. `decidePairing` and `revokeSession` now synchronously require the current verified phase at dispatch; a typed `DispatchBlockedError` means no request was sent and creates or replaces no pending intent. Explicit retries use the same boundary. Already-dispatched writes retain their original recovery identity and confirmed library scope. Local-first logout and unauthenticated pairing/polling retain their separate contracts.

The browser regression delays the real pairing-list GET, changes the capability response to an incompatible API version, then releases the GET and observes zero approval POSTs. After periodic reverification, it checks that no pending decision was created and explicitly approves the same pairing once; the retained peer consumes the issuance through its real UI poll.

## C4 exact filename return correction

Epic review found that login-return validation treated a literal backslash in a decoded `page` filename as a path separator; the same blanket control-character filter also rejected representable newline/tab filenames. The canonical route logic now applies the production package path rules to that once-decoded value: reject NUL, leading slash, drive prefixes and empty/`.`/`..` slash segments while preserving exact filename characters. Raw shell URL guards, registered routes and allowed query keys remain enforced; no trimming, normalization, replacement or second decoding occurs.

Pure route logic lives in `src/app/routes.ts` so the same functions used by the React history hook run directly in the Node regression suite. Positive cases include encoded backslash/newline/tab/Unicode/question/hash characters and literal percent-encoded-looking names; negative cases cover external returns, malformed shell controls, unregistered routes/query keys and actual path violations.

## Known limits

- Native transport is typechecked, unit-tested against a fake port and built as a scratch native entrypoint; no real Wails/desktop binding, credential attachment or native event stream exists before TASK-003-05.
- Shell event consumption is liveness-only (stream end triggers a confirmed-state recheck with a bounded backoff); no SSE frame parsing, cursor/resync tracking or event-driven invalidation is claimed — stateful screens own that later.
- The browser harness ran with the Playwright CLI's headless default. The recheck-stability scenario therefore exercised the real visibilitychange handler through a dispatched event (`visibility_kind: synthetic-event-handler`); an actual tab-refocus visibility transition was not observed in this environment and is not claimed. Keyboard/touch coverage applies to the flows this task changed at 1280×800/1440×900 and an 820×1180 emulated touch context.
- Viewport matrix (390×844/844×390/820×1180/1440×900), measured contrast, full responsive/reader flows and the complete keyboard/screen-reader path belong to TASK-003-06.
- Complete pairing/device UX, localization framework and dark-mode manual toggle remain TASK-007-02; hashed-asset immutable caching remains a deliberate non-goal (uniform `no-store`).
- The fault proxy and fixture alias model the documented private-proxy forwarding path on loopback; they are not private ingress, physical-device or remote proof. Fixture `GET /api/v1/status` returns the auth domain identity shape; full daemon status wiring is covered by the root E2E daemon checks, not this harness.
