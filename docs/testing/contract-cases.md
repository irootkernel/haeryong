## Quality and status rules

Use [fixtures](fixtures.md) for deterministic data and focused host-boundary examples and [knowledge quality](knowledge-quality.md) for real-source claim support, reader tasks and semantic maintenance. A syntactically valid citation is not semantic proof. Keep bounded partial contributions visible and use only not_run/pass/fail/blocked for evidence status; needs-rework is a fail reason, not another status; required host/session, data-integrity and exact-source failures cannot be averaged into a passing quality score. Allowed networking and unselected platforms are not failures under this baseline.

Record initial proof and every relevant release regression with exact source/toolchain/html_js_v1/device and actual expected/observed results in [task evidence](../templates/task-evidence.md). No passing implementation result is claimed here.
