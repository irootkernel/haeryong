## Product coverage

The prototype contains eleven routes: Home, Library, Projects, Sources, Reader, Versions, Maintenance, Archive, Trash, Settings and Connect. Import and explanation creation are dialog flows. Reader context covers Files/Pages, Evidence, Notes, Ask and Links; Settings and Maintenance include their supporting sections and sample states.

For a useful walkthrough, open Home, choose an explanation from Library, inspect Files/Pages and the Reader context tools, compare versions, and try the import and connection flows. Then review Maintenance, lifecycle actions and Settings. These screens illustrate the whole product direction; the [existing task sequence](../../tasks/README.md) determines when each feature is implemented.

Behavior, data ownership and acceptance requirements remain in the [UI specification](../../ui/README.md), [information architecture](../../ui/information-architecture.md), [contracts](../../contracts/README.md) and owning tasks. The handoff identifies differences between this R5 visual proposal and the earlier proposed design tokens.

## Reproduce the HTML

From the repository root:

```sh
python3 -B docs/design/prototype/assemble-prototype.py
```

The assembler writes `prototype.html` and the identical convenience alias `haeryong-prototype.html` into this folder. The repository reference path is `prototype.html`; the alias is optional and is generated by the command. Python 3 and its standard library are sufficient.

| Source group | Role |
| --- | --- |

| `grok-product-r5.json`, `grok-management-r5.json`, `grok-settings-r5.json`, `grok-context-r5.json` | Applied R5 fragment edits and CSS. The assembler uses these JSON records; the matching CSS files are readable exports. |

## What has been verified

The R5 review contains 63 captures of the already-open R3 document, including temporary R4/R5 CSS previews. Those observations include the closed navigation backdrop repair at the same 920 x 1324 viewport. Captures at 1280 x 1368 and 920 x 1324 are recorded observations, not a controlled responsive viewport matrix.

The complete R5 HTML and JavaScript were not reloaded into that browser session. New R5 controls and behavior have source or bounded state checks, not a completed browser walkthrough. Phone layouts, the complete keyboard/screen-reader path, measured contrast and actual Wails/private-browser integration remain for the owning implementation tasks. The [handoff](HANDOFF.md) distinguishes those checks from the existing development entry conditions.

The image-embedded review `haeryong-design-review-r5.html`, 63 JPEG/metadata pairs in `audit-r5/`, and `haeryong-design-r5.zip` were delivered separately. They are not installed in this repository folder. Their filenames in historical notes describe that separate review package.

## Historical records and implementation boundaries

The [original brief](00-BRIEF.md) and [review history](REVIEW.md) preserve how the concept was produced. The brief's original working-area restriction is historical; subsequent prototype work uses this canonical folder. The former `docs/design/2026-10-12-grok/` working folder may be removed after refreshing the documentation inventory. Paths and timestamps inside `VALIDATION.json`, `ASIDE-VALIDATION.json`, `MAC-SYNC-R5.json`, `ORGANIZATION.json` and the review history describe the captured revision and original location; they are provenance records, not dependencies on an existing old directory.

The prototype's restrictive inline CSP, synthetic authentication, simulated AI/file operations and in-memory state are demo fixtures. Product code must implement the existing viewer, authentication, source, storage and job contracts. In particular, the product's normal JavaScript and external-resource behavior follows the [viewer protocol](../../contracts/viewer-protocol.md), not this offline demonstration's `connect-src 'none'` policy.

This prototype supports implementation decisions. Actual task completion and gate evidence follow the [execution protocol](../../execution-protocol.md).
