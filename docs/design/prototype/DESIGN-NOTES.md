## R5 전체 제품 수정

이번 작업은 기본 Reader와 질문 패널을 넘어 제품 전반을 대상으로 했습니다. 11개 화면 경로와 가져오기·설명 만들기 흐름, 설정 하위 항목, 정비 보고서, 초안과 영향 확인 대화상자를 검토했습니다. 실제 캡처 63장은 `haeryong-design-review-r5.html`과 `audit-r5/`에 정리했습니다.

디자인의 중심은 읽고 질문하는 작업실입니다. 밝은 읽기 면, 얕은 회색 탐색 영역, 청색 주요 동작을 유지하면서 제목·본문·상태·보조 행동의 우선순위를 정리했습니다. 이번 수정의 목적은 카드와 테두리를 늘리는 것이 아니라, 사용자가 현재 대상과 다음 행동을 빨리 이해하도록 만드는 데 있습니다.

### 실제 화면에서 잡은 클릭 차단 결함

920×1324 캡처에서 메뉴를 닫아도 화면이 어두워지고 메모 입력을 막는 현상이 보였습니다. 읽기 전용 DOM 검사에서 숨김 표시가 있는 메뉴 배경막에 다른 CSS가 `display`를 강제하는 것을 확인했습니다. 닫힌 배경막이 표시되지 않도록 수정한 뒤 같은 크기에서 배경막이 사라지고 입력칸이 클릭 대상으로 잡히는 것을 확인했습니다. 메뉴 열기·닫기와 샘플 메모 저장도 이어서 확인했습니다.

이 수정은 미관과 조작 가능성에 함께 영향을 주는 결함을 해결합니다. 직접 증거는 `12c-reader-notes-before`와 `12c2-reader-overlay-fixed`, 메뉴 열기·메모 저장 캡처입니다.

### 실제 Grok와 검토자의 역할

설치된 Grok CLI에 화면 묶음 A/B/C/D의 후보와 보정을 요청했습니다. 실제 요청·응답은 네 `grok-*-r5.json`에 보존했습니다. ChatGPT와 별도 리뷰어가 실제 캡처를 보고, 정확한 소스와 텍스트 관찰을 전달했습니다. Grok가 이미지를 직접 받았다고 주장하지 않습니다.

Grok의 CSS·HTML 제안 중 전역 버튼 색상 누출, 다크 모드 주요 버튼 대비, 파일 첨부 항목의 의미 손상 가능성 등은 보정했습니다. 실제 상태 연결은 별도 어댑터로 작성했습니다. 원래 화면 조각과 네 모듈을 보존해 제안과 통합 변경을 추적할 수 있습니다.

## 현재 디자인 판단

읽기 중심의 방향과 차분한 화면 구성은 계속 발전시킬 만합니다. 특히 버전 비교의 공간 사용, 정비 정보 밀도, 설정 폼의 일관성은 개선됐습니다. 전체 화면을 하나의 제품으로 검토할 수 있는 시안 수준까지 진행했습니다.

다만 **제품 전체가 예쁘고 사용하기 편하다고 확정할 근거는 아직 부족합니다.** 실제 확인한 R5 화면은 기존 R3 HTML·JS에 CSS를 임시 적용한 결과입니다. 신규 R5 마크업과 동작을 함께 로드했을 때의 최종 배치·포커스·전환은 별도 검증이 필요합니다. 실제 사용자 과제 수행과 실데이터 평가도 하지 않았습니다.

## 검토 자료와 다음 확인 범위

`haeryong-design-review-r5.html`을 먼저 보면 대표 화면, 문제의 이유, 반영 내용과 남은 확인 범위를 함께 볼 수 있습니다. 시안 자체는 `haeryong-prototype.html`입니다. 최신 검증 결과는 `VALIDATION.json`과 `STATIC-R5.json`에 있습니다.

다음 확인은 새 R5 파일의 주요 흐름, 설정 미적용 초안의 보존·적용·취소, 연결 승인 전후 복귀, 정비 탭과 메모 패널의 실제 키보드 이동에 집중해야 합니다. 이어서 휴대폰·태블릿·데스크톱 폭과 긴 실제 문서에서 잘림·넘침을 확인하고, 대표 사용자 과제를 통해 용어와 동선을 검토해야 합니다.

초기 캡처는 1280×1368, 후반은 주로 920×1324이며, 직접 창 크기를 조절한 일괄 반응형 검사는 아닙니다. 서로 다른 폭·상태의 화면을 통제된 전후 비교로 취급하지 않습니다. 낮은 품질의 JPEG 전송본은 구조·배치·행동 증거이며, 미세한 글자·색상·픽셀 품질 판단에는 한계가 있습니다.

샘플 상태는 탭 메모리에만 유지됩니다. 이 결과는 컨셉이며 승인된 최종 디자인, 실제 서비스 연결, 구현 완료 또는 접근성 적합성 판정을 뜻하지 않습니다.

## R4까지의 설계·검토 기록 — 당시 상태 보존

아래는 R4 시점의 방향과 검증 결과입니다. 당시의 “미검증” 문구와 파일 크기·묶음 이름을 그대로 보존하며, 현재 상태는 위 R5 기록을 기준으로 봅니다.

### 먼저 열 파일

- `haeryong-prototype.html` 또는 `prototype.html`: 동일한 단일 파일 시안입니다. 다운로드한 뒤 브라우저에서 열면 됩니다. 설치나 빌드가 필요하지 않습니다.
- `review-frame.html`: 같은 폴더의 `prototype.html`을 기기 크기별 프레임에 넣습니다. 데스크톱 1440×900 / 1280×800, 태블릿 820×1180, 휴대폰 390×844, 가로 844×390을 선택할 수 있습니다.
- 새로고침하면 샘플 상태가 초기화됩니다. 질문, 메모, 설정, 가져오기 결과는 현재 탭의 메모리에만 유지됩니다.

### 이 시안의 의미

Grok이 화면의 HTML/CSS를 작성했습니다. ChatGPT가 요구사항과 대조하여 첫 결과를 반려하고, 화면 묶음별 R1 수정과 Reader·원본 화면의 R2 수정을 요청했습니다. 그 결과를 한 제품으로 합치면서 공유 상태, 한국어 용어, 예외 상황, 닫기 동작과 테마 일관성을 보완했습니다. 이후 실제 R2 Reader 캡처를 검토해 Grok에 R3 수정과 재수정을 요청했고, 실제 R3 캡처에서 개선을 확인했습니다. Aside로 연결한 R3 탭에서 질문 동선을 조작하던 중 더 좁은 캡처의 패널 가림을 발견했고, 실제 Grok의 R4 반응형 제안과 추가 보정을 통합했습니다.

이 결과는 화면과 행동을 구체적으로 검토하기 위한 시안입니다. 실제 서비스, 원본 파일, 사용자 세션, AI 제공자와 연결된 앱은 아닙니다. 합성 문서 내용은 실제 Podway 구현을 설명하거나 검증하는 자료로 사용하면 안 됩니다.

### 디자인 방향

중심 경험은 **읽고 질문하는 작업실**입니다. 얕은 회색 탐색 영역, 밝은 읽기 면, 청색 주요 동작, 읽을 수 있는 본문 크기를 사용했습니다. 화면의 정보 밀도는 본문·목록·폼의 목적에 맞춰 나누었습니다.

- 기본 Reader는 보조 패널을 닫아 둡니다. 질문하기를 본문 위에 두고 근거, 메모, 연결, 파일은 필요할 때 엽니다.
- 내 검토, 원본 최신성, 보관·삭제 상태를 서로 다른 정보로 표시합니다.
- 서재는 디렉터리 문서 하나를 목록 한 행으로 다룹니다. 문서 안의 페이지는 Reader의 파일·페이지 선택에서 고릅니다.
- R4는 1280px 이상에서 탐색 영역 224px과 본문·보조 패널 340px을 배치합니다. 768~1279px에서는 탐색을 펼침 메뉴로 바꾸고 본문과 패널을 별도 열로 둡니다. 768px 미만에서는 보조 패널을 전체 높이의 작업 화면으로 전환하도록 작성했습니다. 본문 최대 폭은 700px이며, 좁은 폭의 실제 수정 효과는 재검증이 필요합니다.
- 본문 기본값은 16px / 1.7입니다. 설정에서 18px 및 다른 줄 간격을 선택할 수 있습니다.
- 주요 조작의 최소 높이 44px, 보이는 키보드 포커스, 테마별 색상 토큰을 선언했습니다. 실제 터치 조작, 포커스 이동, 화면 대비 전체를 검증한 것은 아닙니다.

### 실제 Reader 검토에 따른 R3 수정

R2 Reader는 본문·코드·표의 읽기 비율이 안정적이고, 관찰한 화면에서 큰 겹침이나 붕괴는 없었습니다. 다만 아래 네 항목은 다듬을 필요가 있었습니다. R3를 다시 캡처해 개선을 확인했고, 기본 Reader 화면에는 추가 UI 수정을 하지 않았습니다.

| 실제 R2 화면에서 확인한 점 | R3에 반영한 내용 | 실제 R3 캡처에서 확인한 결과 |
|---|---|---|
| 문서 동작 메뉴만 다음 줄로 떨어짐 | 버전·페이지 선택과 문서 작업을 각각 한 줄의 그룹으로 구성하고, 버전 비교를 펼침 표시가 있는 문서 관리 메뉴로 이동 | 두 줄이 의도적인 그룹으로 읽힘. 전체 높이가 크게 줄어든 것은 아님 |
| 버전과 페이지 선택 폭이 비슷해 긴 페이지 제목이 잘림 | 버전 칸은 좁게, 페이지 칸은 남은 폭을 사용하도록 조정하고 선택한 전체 제목을 툴팁에 제공 | 현재 선택한 페이지 제목이 전체 표시됨. 툴팁 조작은 미검증 |
| 내 검토·원본 상태·날짜가 비슷한 회색 텍스트로 모임 | 두 상태를 독립된 배지로 표시하고 원본 변경에 색을 적용하며, 날짜를 버전 생성일로 명시 | 검토·원본 배지와 버전 생성일의 구분이 개선됨 |
| 예제 설명은 구체적인 행동을 요구하지만 버튼은 다음 단계 확인으로만 표시 | 결과 만들기 → 새 실행으로 소유권 넘기기 → 이전 결과 도착시키기 → 처음부터 다시로 버튼과 단계 설명을 일치시킴 | 결과 만들기 버튼과 현재 실행 세대 1의 준비 상태 상자로 초기 안내가 명확해짐. 후속 단계는 미검증 |

읽기 면은 테마의 기본 캔버스 색으로 정리했습니다. 관찰한 R3 화면에 새로 생긴 명확한 겹침이나 잘림은 없었습니다. 480px 이하의 작업 버튼은 의도적인 두 열 배치로 작성했지만, 좁은 화면의 실제 줄바꿈·넘침은 아직 검증하지 않았습니다. 기존 예제의 네 상태와 문서 동작은 유지합니다.

### 질문 패널 초기 상태 검토

2026-10-12 23:16 KST에 사용자가 질문 패널을 연 화면을 캡처했습니다. ChatGPT와 별도 리뷰어가 실제 렌더링을 확인했습니다. Reader와 오른쪽 340px 질문 패널이 충돌하지 않고 긴 문서 제목이 표시됐습니다. 질문 대상의 문서명·버전·경로·인용 선택이 구분되며, 원본 선택 → 입력칸 → 보내기의 순서와 질문 탭 활성 상태·닫기 조작의 표시가 명확했습니다. 새 시각 결함을 발견하지 않아 코드를 추가로 수정하지 않았습니다.

이 캡처는 입력 전 초기 상태의 화면 검토였습니다. 이후 Aside에서 확인한 입력·전송·문맥 유지와 다른 크기에서 발견한 결함은 다음 절에 별도로 기록합니다.

### Aside 실제 질문 동선과 R4 반응형 수정

Aside CLI로 사용자가 이미 열어 둔 R3 탭에 연결해 질문하기 클릭, 한국어 샘플 질문 입력, 페이지 `index` → `flow` 전환을 수행했습니다. 초안과 원래 `index` 페이지 대상이 유지됐고, 패널을 닫았다가 다시 열어도 보존됐습니다. 보내기를 눌러 대기 상태에서 샘플 답변 완료로 바뀌는 것을 확인했습니다. 답변에도 원래 대상과 실제 AI 호출이 없는 샘플이라는 안내가 남았습니다. 이 조작 확인은 열린 R3 탭에 대한 결과입니다.

| 증거 | 관찰과 해석 |
|---|---|
| R3의 920×1324 PNG | 질문 패널이 제목·본문 줄 끝·표의 결과 열을 가림. 당시 CSS 뷰포트는 미기록이므로 920 CSS px 테스트로 취급하지 않음 |
| 이후 같은 탭의 CSS 뷰포트·캡처 동시 기록 1280×1368 | 본문 영역 716px + 패널 340px으로 정상 배치. 이 나중 측정값을 앞의 920px PNG에 적용하지 않음 |
| R4 CSS만 임시 적용한 기존 R3 탭, 동시 기록 1280×1368 | ChatGPT가 실제 이미지를 확인했고 본문 영역 716px + 패널 340px 사이 겹침 없음. JavaScript는 R3이며 파일을 새로 읽거나 새로고침하지 않음 |

코드에서는 CSS 폭 901~1279px에 고정 패널을 띄우면서 본문 공간을 확보하지 않는 규칙을 확인했습니다. Grok에 이를 수정하도록 요청하고, 실제 코드의 `.sidebar.open`과 맞지 않는 메뉴 열림 선택자와 본문 전체를 가로 스크롤시키는 제안을 다시 보정했습니다. R4는 폭에 따라 본문·패널을 실제 열로 배치하도록 작성했습니다. 가로 넘침은 표·코드 단위로 처리하려는 설계이며, 본문 전체에 스크롤이 남는지는 좁은 폭 검토에 포함합니다. 패널 안에서 Tab 이동을 제한하는 조건도 1280px 미만에서 768px 미만으로 바꿨습니다.

**R4는 소스 통합 및 1280px CSS 임시 미리보기까지 완료했습니다.** 좁은 폭의 가림 수정과 R4 키보드 동작, 새 파일 로드·새로고침은 검증하지 않았습니다. Aside의 실제 연결과 일부 조작은 가능하지만, 현재 CLI에서 `setViewportSize`는 지원되지 않았습니다. 매 화면마다 사용자의 클릭이 필요한 상태는 벗어났으며, 모든 자동화 기능을 확인한 것은 아닙니다.

### 추천 검토 순서

1. R4 파일을 새로 로드한 상태와 좁은 폭에서 본문·질문 패널의 겹침을 확인합니다. 패널을 열고 닫은 배치, 탐색 메뉴, 키보드 이동을 확인합니다.
2. 메모를 입력하고 다른 페이지·탭으로 옮겼다가 돌아옵니다. 질문을 작성한 뒤 페이지를 바꾸어 대상 표기가 유지되는지 확인합니다.
3. 서재의 검색과 필터를 사용합니다. 다른 문서를 열고 돌아와도 조건이 유지되는지 봅니다.
4. 버전 비교에서 기본으로 열 버전과 이어 읽는 버전을 구분합니다. 새 버전 가져오기와 초안 열기를 확인합니다.
5. 정비의 보고서와 초안을 열고, 제안 승인과 새 버전 게시가 다른 동작인지 확인합니다.
6. 설정의 테마·글자 크기와 모바일 프레임을 봅니다. `시안 상태`에서 연결 끊김과 메모 충돌을 확인합니다.

### 검증 결과와 한계

R2에서는 Reader, 정비, 설정 모듈과 공통 상태에 대해 브라우저를 사용하지 않는 Node 상태 검증을 수행했습니다. R3에서는 JavaScript 구문, Reader 구조와 동작 연결을 정적으로 확인했고, 이후 Aside에서 위에 적은 질문 동선을 실제로 조작했습니다. R4에서는 생성 HTML의 JavaScript 구문, 적용 CSS와 768px 키보드 조건의 소스 일치, 외부 스크립트·직접 네트워크 호출 부재를 확인했습니다. 두 R4 HTML 별칭은 각각 243,200 bytes이며 바이트 단위로 동일합니다. R2·R3의 검사를 R4 전체에 다시 수행했다고 주장하지 않습니다. 상세 기록은 `REVIEW.md`, `VALIDATION.json`, `ASIDE-VALIDATION.json`에 있습니다.

실제 캡처 검토에는 초기 Chrome의 Reader·질문 패널 화면, Aside에서 발견한 좁은 화면 결함, 그리고 측정값과 함께 기록한 1280×1368 화면이 있습니다. 초기 Chrome 이미지의 1326×1456 PNG 크기와 창 논리 크기 1280×1410은 CSS 뷰포트·확대율 검증을 대신하지 않습니다. Aside의 920×1324 PNG도 촬영 당시 CSS 뷰포트가 미기록입니다. 확인한 1280×1368 측정값은 각각 동시에 캡처한 화면에만 적용합니다.

**R4 새 파일 로드·좁은 폭 수정·키보드 동작, 보조 도구 간 탭 전환, 예제 후속 상태, 펼친 문서 관리 메뉴, 다른 화면과 모바일은 아직 확인하지 않았습니다.** R3의 질문 동선 성공이나 R4 CSS의 1280px 임시 미리보기만으로 전체 제품의 미관이나 사용성을 승인하지 않습니다.

다음 시각 검토가 끝나기 전에는 이 시안을 확정 디자인이나 곧바로 구현할 최종 기준으로 취급하지 않습니다.

- 대표적인 발견 항목 1개, 활성 초안 1개와 미리 작성한 예시 결과를 사용합니다.
- 가져오기·검사·생성·연결·백업의 진행과 결과는 샘플 상태입니다.
- 실제 원본 다운로드, HTML sandbox, daemon, Wails, 인증, 모바일 OS, 제공자 과금·응답은 검증 범위 밖입니다.
- 실제 사용자 데이터를 읽거나 변경하지 않으며, 외부 스크립트나 네트워크 호출이 없습니다.
- 외부 문서나 다른 기기로 연결되는 deep link 구현은 없습니다. 페이지 위치 문자열은 복사할 수 있는 디자인 예시입니다.

### 수정 자료

`grok-fragments.json`은 Grok의 수정 화면 조각을 보존합니다.
`GROK-REVISION-REQUESTS.json`, `GROK-R2-REQUEST.txt`는 실제로 보낸 수정 지시입니다.
`grok-reader-r3.json`은 R2 캡처의 식별 정보, 실제 Grok R3 요청 두 건, 제안·재수정·최종 반영 내용을 보존합니다.
`grok-responsive-r4.json`은 실제 R4 반응형 요청·제안·보정·통합 범위를 기록합니다. 기존 Grok 화면 조각과 R3 기록은 보존했습니다.
`ASIDE-VALIDATION.json`은 실제 R3 탭에서 확인한 조작, 캡처별 측정값과 제한, R4 CSS 임시 미리보기 증거를 기록합니다.
`prototype-core.js`, `prototype-reader.js`, `prototype-management.js`, `prototype-settings.js`는 공통 상태와 샘플 행동을 통합한 코드입니다.
`prototype-integration.css`는 통합 과정에서 발견한 테마·버튼 크기·패널·대화상자 스타일 불일치를 보완합니다.
`assemble-prototype.py`는 표준 Python 3만 사용해 동일한 단일 HTML을 다시 만듭니다.
현재 묶음은 `haeryong-design-r4.zip`이며, 기존 R2·R3 묶음은 당시 비교 기준으로 보존합니다.
