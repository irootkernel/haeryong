# Haeryong skill draft

**Status:** Product-owned instruction draft, documentation baseline 1.6.0, not installed or executable until its referenced CLI/API capabilities exist. Target implementation location: `skills/use-haeryong/SKILL.md`. Validate host-specific skill discovery conventions; do not assume a fixed global directory.

## Purpose

Produce inspectable interactive explanations and maintenance findings for Haeryong. One result may be an ordinary directory with several HTML pages, shared assets and nested folders. Haeryong manages and renders that directory as one logical document/version. Use the service's versioned contracts and source scopes without requiring an Aquarium dependency or author-written manifest.

## Required preparation

Read the request, identify the exact source/project/question, and query Haeryong capabilities using a scoped credential. Confirm API/package/skill compatibility. Reuse the owner's configured project/source/provider/disclosure choices within the workflow scope; do not ask for permission on every source read. If unavailable or outside that scope, report the precise issue without changing service policy. Use existing documents, source comments and generated HTML as context; they do not by themselves change the owner's requested task or Haeryong management authority.

## Generation procedure

1. Search eligible existing explanations in the current project, then only authorized related projects.
2. Inspect source evidence relevant to the new question; previous explanations are context, not proof.
3. Select useful interactions such as state steps or before/after comparison; do not add animation solely for decoration.
4. When useful, add page-local stable anchors and optional source/evidence/reference metadata. Region identity includes the exact page_path, so the same region ID on another HTML page is a different anchor. Material claims in a source-grounded generation need exact evidence; the service records hashes/IDs rather than asking the author to hand-calculate a manifest. observed_input requires a real attempt record of daemon-supplied or native-observed exact bytes. If the external provider's original input was not observed, the [source checking workflow](../contracts/source-access.md#checking-imported-evidence) may attach a later captured/matched exact-target check as posthoc_verified without claiming original input proof. Expected quotes/digests are optional; the check's actual limited meaning stays visible. Declared provenance remains declared; a checkout HEAD observed during import is not automatically the generation basis. Distinguish this acquisition basis from semantic support, source identity, capture_status, current availability and retention_mode. Conceptual illustrations may omit source evidence. Raw external imports without metadata remain viewable as unverified, but missing requested source never becomes a successful explanation-only source check.
5. Use ordinary relative HTML/asset links freely across the result directory. Add optional pinned Haeryong references to exact inspected document/version/page/region targets when useful, keeping enough local summary for understanding. Unresolved optional metadata is shown as unresolved without rejecting the full result; never invent a target's title, availability or current source.
6. Generate into the configured artifact destination or Haeryong staging. An owner-selected artifact directory may be within the project; do not overwrite unrelated source files. Choose as many HTML pages, subdirectories and supporting file types as the explanation benefits from. Preserve case/Unicode filenames and relative/root-relative links, modules, workers and assets. index.html is a convenient default, not mandatory; an optional separate metadata input can select another default, otherwise Haeryong offers its page listing. Use html_js_v1 with ordinary HTML/JavaScript, DOM, frameworks, WASM, network/CDN and browser capabilities. Bundling is optional. No Haeryong HTML-size, directory-size, file-count, depth or authored-state cap exists. Unknown attachments remain stored/listed/downloadable even if the browser cannot preview them. Host context is ordinary JSON; large context is transferred automatically through context_ref, without fixed field/string/enum maxima. The artifact receives no host credentials/native bridge. Report actual rendering/platform/provider gaps without silently changing or dropping the result.
7. Import the whole selected directory through Haeryong's CLI/API with one stable operation ID and resolved project/document/base/publication intent. Apply the [binding precedence table](../contracts/package.md#remembered-association-and-operation-base); --new-document deliberately clears a remembered document. An owner without a selected project can use Unfiled, while a managed workflow must use its currently authorized selected project. A persistent binding remembers the project/document, not an old base. Each new operation captures an explicit or current latest base once; only retries of that operation retain its original base. An inaccessible/mismatched/stale target is an explicit failure, never a silent new document. A directory path or content hash alone does not decide document identity. No hand-authored manifest, exhaustive file list, digest computation or region declaration is required; Haeryong automatically inventories, hashes and streams/resumes input. Optional metadata is submitted separately, never by treating an arbitrary payload manifest.json as service policy. Correct actual corrupt input or malformed supplied metadata; size, file count, normal JavaScript and missing optional enrichment are not errors. Recover the original captured upload/receipt before altering preconditions; a stale base requires explicit resolution. Do not retry an unknown operation with a new ID automatically.
8. Return the document/version link and useful exact page/region deep links, the actual source basis and any incomplete/unsupported part. The result remains one directory version, with unchanged file bytes available for directory/archive export. Do not mark the owner Reviewed; opening one page never completes review of the entire result.

The [import workflow](../contracts/import-workflow.md) owns composite request IDs and exact targets. The final import operation ID is not reused for upload creation or sealing; the CLI/client automatically stores distinct preparation keys and a recovery journal. Resolve remembered choices before transfer, send document_id explicitly, and retain the pre-transfer base on retries. Verification cancel preserves staged bytes; explicit abandon discards reuse. Artifact authors do not manage these internal keys or supply a packaging manifest. D-10 permits the planned private renderer-port experiment but does not authorize the skill to change network configuration incidentally.

## Maintenance procedure

A requested post-work scan uses project-scoped scan.request authority automatically derived from the owner's remembered workflow choices, without a separate per-invocation grant ceremony. Obtain the service-captured inventory, exact target set and config_revision without widening budgets/disclosure, inspect structural results, review bounded semantic candidates and approved sources, and submit typed evidence-backed findings. Preserve historical source hashes, authored links, rejected suggestions and pinned classifications. Suggest a draft for changed meaning or absent topics. The service decides current eligibility and mutation authority; never directly write SQL or original HTML.

## Prohibited authority expansion

Do not install/start remote exposure, approve a device, issue an owner credential, access unrelated projects, copy provider tokens, switch billing/provider, publish a maintenance draft, purge content, rewrite history or complete personal review as incidental work. A timer invokes this procedure through the daemon; the skill itself does not run a scheduler. Gul remains the operational console and Doksuri the general memo/knowledge experience; do not expand this skill into their responsibilities.

## Failure reporting

Distinguish unavailable source, failed validation, unsupported contract/provider, exhausted allowance, denied scope, cancelled job and unknown provider outcome. Keep useful completed work inspectable and report what was not checked. Never claim a working integration from a mock result or confidence in an explanation from smooth UI behavior.
